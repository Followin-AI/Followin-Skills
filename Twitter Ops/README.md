# Twitter Ops — 推特日运营工作流

**一句话**：一个人做加密 / 宏观 / 美股方向的内容账号，每天那套「扫热点 → 选题 → 写稿 → 互动 → 复盘」，这 7 支把它做成流水线——数据从 Followin MCP 实时拉，判断按预设规则跑，**稿子出到终稿为止，发布永远由你按按钮**。

## 它替你干的活

一个人运营账号，每天的固定开销是这条链：

翻十几个信息源看今天有什么值得说的 → 判断哪几条你真能接上话 → 写成推文 → 去别人帖子下留有价值的评论 → 处理自己评论区 → 周末复盘哪条数据好、为什么。

难的不是任何单步，是**每步都要判断、而判断需要实时数据**：哪条热点真有交易标的、你的角度会不会和对标账号撞车、推文里的涨跌幅是不是最新的、评论区哪条是真质疑哪条是刷单广告、这周数据到底是自己跌了还是全行业在跌。这 7 支就是把这些判断固化成规则、把数据接到 MCP 上。

---

## 7 支各干什么

| Skill | 触发词 | 干什么 |
|---|---|---|
| **twitter-ops** | 「跑一轮」「手动跑一轮」 | 调度器：串起全流程、管自动/手动模式切换、在检查点停下等你。**「发布必须人工确认」这条红线在这里** |
| **trend-scout** | 「扫一下热点」 | 多路并行拉市场数据（list / 新闻 / TG 资金流 / 链上），产出结构化简报。**实时数据区和叙事区强制分开**——硬数字归硬数字，观点归观点 |
| **topic-engine** | 「今天发什么」 | 热点 → 可写的角度，按时效/差异化/可信度打分排序。**层 B 差异化**：拉对标账号近期推文，判你的角度是不是已经被写过（撞了就砍或换角度） |
| **tweet-composer** | 「帮我写推文」 | 出稿。单条 / Thread 原创 / 长文拆 Thread 三种模式，含字符预算、事实核查 6 维、发布前终检 |
| **engagement** | 「今天该跟谁互动」「看看我评论区」 | 两头都管：**Outbound** 去别人高互动帖下抢优质评论位，**Inbound** 给自己评论区分级并出回复稿 |
| **performance-review** | 「这周数据怎么样」 | 周复盘：行业基线对照、北极星目标、内容类型效果、爆款/失败归因，顺手把好稿入素材库 |
| **competitor-watch** | 「竞对在发什么」 | 对标账号监控——学手法，也看自己在坐标系里的位置 |

## 怎么用

### 装

这 7 支是 Claude Code 的 skill。把 `skills/` 下的目录拷进 `~/.claude/skills/`：

```bash
# ⚠️ 先看会不会覆盖你已有的同名 skill（名字是通用词，容易撞）
ls ~/.claude/skills/ 2>/dev/null | grep -E "trend-scout|topic-engine|tweet-composer|performance-review|competitor-watch|engagement|twitter-ops"

# 没输出 → 安全，直接拷
cp -rn "Twitter Ops/skills/"* ~/.claude/skills/

# 有输出 → 先备份再拷：
# cp -r ~/.claude/skills ~/.claude/skills.bak && cp -r "Twitter Ops/skills/"* ~/.claude/skills/
```

> ⚠️ **`-n` 不能省。** 不带 `-n` 的 `cp -r` 会**静默覆盖**你已调好的同名 skill。

### 填配置（装完直接跑，它会引导你）

装完说「跑一轮」，**它会先拦住你**——检测到配置还是模板时不往下跑，而是告诉你缺哪几项、怎么填。所以你不用先背配置表。

**最少只填 [`config.md`](./config.md) 里 🔴 的三项**（你的账号 + 两个目录路径），其中两个已给默认值，实际只需填账号一项。填完就能跑「只扫热点」验证 MCP 通不通。

📌 **没有 Twitter list？** `config.md` 里给了一个公开示例 list（`main=2046422494643687464`）可以先拿去跑通，但**它是示例不是默认**——约 17% 内容与市场无关、产权不在你手上，跑通一次后建议换成自己建的 list。理由 config.md 里写了。

除 config.md 外还有几份**内容型**配置（人设语气 / 运营目标 / 对标名单），可以让 Claude 帮你从历史推文生成——各文件里都写了「怎么填」，装完让它引导即可。

### 跑

| 你说 | 效果 |
|---|---|
| 「跑一轮」 | 自动模式——全程按规则决策，直接出终稿 |
| 「手动跑一轮」 | 每个检查点停下等你确认 |
| 「扫一下热点」/「今天发什么」/「帮我写推文：[主题]」 | 只用某一块 |
| 「看看我评论区」/「竞对在发什么」/「这周数据怎么样」 | 互动 / 对标 / 复盘 |

两种模式随时可切：自动模式跑着时你发任何一句话，它就在当前节点停下变手动。

## 几条设计取舍（都是被实测打磨过的）

- **发布永远不自动。** 所有模式最终停在终稿，等你按发布。账号是你的。
- **数据和观点强制分区。** 简报里实时数据区只放能追溯到 API 的硬数字，新闻/KOL 观点进叙事区并标时间。最容易出的事故是：拿三小时前新闻里的涨跌幅当现价写进推文。
- **写稿前会再拉一次价格。** 从扫热点到出稿可能过了十几分钟，行情已经变了。
- **破坏性动作绝不建在没定义的标准上。** 砍稿、砍候选这类不可逆动作，只要依赖的阈值/口径在配置里查不到，一律「只标注不执行」——不拿自己编的标准去砍真东西。

## 已知限制

- **只覆盖单账号运营。** 多账号矩阵、跨平台分发不在范围内。
- **互动与复盘需要你先填名单**——没有 KOL 目标和对标账号，这两块跑不出东西。
- **数据源单一。** 全部依赖 Followin MCP，它挂了整条链就停。
- **输出是终稿不是发布。** 没有自动发推能力，也不打算加。
