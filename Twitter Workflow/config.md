# 运行期配置

> **所有 Skill 读这一份。** 各 SKILL.md 的 §0 只定义变量含义，值统一填在这里。
> 没填的变量，Skill 会按「未填 → 跳过对应规则并如实标注」处理——但下面标 🔴 的三项不填就跑不动。

---

## 🔴 必填（不填流水线会被自查拦死）

| 变量 | 值 | 说明 |
|---|---|---|
| `ACCOUNT` | `@___` | 你的运营账号。**所有拉自家数据的调用都锚在它上面**。⚠️ 与 MCP 登录账号无关 |
| `STATE_DIR` | `~/.claude/state/` | 跨天状态与候选池目录。**别用 `/tmp`**——重启即清空，第二天选题直接扑空 |
| `BRIEF_DIR` | `~/.claude/briefings/` | 简报输出目录 |

> 后两项给了默认值，可以直接用。`ACCOUNT` 必须自己填。
>
> ⚠️ **标了「出厂默认」的值是我们替你猜的，不是你的决定。** 各 Skill 会把它们当真配置执行
> （`CATEGORY_CAP` 是 topic-engine 的硬闸），所以要么确认一遍、要么改掉，
> **改过之后把 `⚠️出厂默认` 这个标记删掉**——留着它就是在说"这个数没人拍过板"。

| 变量 | 值 | 说明 |

> 不许当成"今天这个 list 没人发推"。

## 怎么填得快一点

**没有 list、不知道放谁**：先只填 🔴 三项，跑「只扫热点」看看能拿到什么。
trend-scout 会如实标注哪几路因为缺配置跳过了，你据此再补。

**不知道 `BENCHMARK_KOLS` 放谁**：说「**帮我分析历史互动对象**」，
它统计你实际回复最多的账号——那些是天然候选，比凭印象列准。

**`ACCOUNT_ENGINES` 想不清楚**：先留空跑两周，然后跑 `performance-review`，
用真实互动数据反推你实际在写什么、读者实际在看什么。**那时候填的比现在猜的准。**

## 开工四检（所有 Skill 直接触发时都适用）

用户可能直接说「这周数据怎么样」「竞对在发什么」而**不走 `twitter-ops` 调度器**，
此时调度器的初始化闸门不会执行。各 Skill 的 §0 都会回头执行这四条，**完整判据只维护在这里一处**：

**① 账号锚定** —— 所有拉自家数据的调用一律用上面的 `ACCOUNT`（唯一权威）。
仍是 `@___` 或找不到 `config.md` → **停下来让用户先填**，别拿占位符去调 API。
⚠️ `ACCOUNT` 与 MCP 登录账号无关：登录账号只决定"能不能发推"，不决定"分析谁的数据"。

**② 目录** —— 落盘走 `STATE_DIR` / `BRIEF_DIR`。🔴 **指向 `/tmp` 直接停下来报错**，这是硬检查不是提示。
🔴 **同样必须是绝对路径**（`~/` 或 `/` 开头）：相对路径（`./state`）会跟着**会话启动目录**漂——
今天在 A 目录跑、明天在 B 目录跑，写的就是两个 state，跨天资产照样丢，且和 `/tmp` 一样不报错。`~` 要展开成真实家目录。
`/tmp` 重启即清空，后果是：回填静默退化成全 null（不报错）、第二天选题直接扑空、
打分-效果回验的 join 源消失。**修 `/tmp` 问题时要把同目录所有跨天资产一起清点，不是只搬报错的那个。**

**③ 时钟** —— 每轮开工第一件事，用 shell 现取一次，全程只用这一组值：

```bash
DATE=$(date +%F)           # 2026-07-30
WEEK=$(date +%G-W%V)       # 2026-W31 —— ISO 周，跨年不漂
NOW_MS=$(( $(date +%s) * 1000 ))
```

🔴 **禁止凭模型自己的日期认知推算日期或周数。** 模型的日期偏差常达数月，而这几个值被当**文件名**用——
猜错就写进错误日期的文件，下一轮查重扑空、读不到今日产物、回填链断，
而**全程不报错、产物格式齐全**。这类静默错误比崩溃难查得多。
周编号**只认 `%G-W%V`**（`2026-W31`），全仓任何周文件名都用它拼。

**④ 「文件存在但仍是占位符」= 视同没有** —— 各 Skill 依赖的 reference 文件出厂时**都存在**，
内容却是 `@[账号1]` / `[例：…]` / 无标记的默认百分比。**只判「文件不存在」的逃生永不触发**，
模型会把模板值当真配置读进去并据此打分——不报错、不阻塞、直接产垃圾。

判定：出现 `[…]` 方括号占位、`___` 下划线占位，或小节顶部带
`<!-- INIT-STATUS: template-default -->` 状态位 → **一律按未配置处理**，
记 `n/a` 并在输出显式标注。⚠️ 只检**必填项**，不检整份文件——文件是分阶段填的。

> 💡 **例外**：方括号里写的是"算法"而不是"要填的空"时不算占位符
> （如 performance-review 北极星表的 `[当前中位 ×1.3]` 是让你算出来，不是等人填）。

## ⚠️ 一次只跑一个

**不要在两个终端里同时跑两个 Skill。** 这套东西没有文件锁，多个 Skill 共享同一批状态文件：

- 日简报被 trend-scout 和 topic-engine 共同追加，frontmatter 还要读-改-写（并发会撕裂）
- 候选池索引 `-latest.txt`、`last-refresh-*.txt` 都是读-改-写（一方的写入会被另一方覆盖）
- 弧线计数 `days_hit++`、周配额 `week_published_count` 是非原子自增（会丢计数或双计数）

**这些冲突不会报错**，只会让下一轮读到错的数。串行跑，一轮跑完再跑下一轮。

## 校验

填完可以让 Claude 自查一遍：

> **「检查 config.md 填全了吗」**

它会核对三件事：🔴 三项是否都有值 · `MAIN_ENGINE_TYPES` 是否和 operations-plan §三 对得上 ·
`STATE_DIR`/`WORK_DIR`/`BRIEF_DIR` 是否都不是 `/tmp`**且都是绝对路径**（相对路径会跟着会话目录漂）。

> ⚠️ **还有一条查不了**：各 Skill §0 要求日期用 shell 现取（`date +%F` / `date +%G-W%V`），
> 而这是**运行时行为**，看 config.md 看不出来。想验它就跑一轮，
> 看落盘文件名里的日期和周数对不对得上今天。
