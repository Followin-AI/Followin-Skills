# 互动运营 Engagement

一套工具两件事：**Outbound**（去别人的高互动推文下抢优质评论位，换曝光和关注）+ **Inbound**（把自己推文的评论区当阵地：分级、回复、借势）。评论区是算法燃料（对话权重极高）+ 信任展示位，**回复是写给围观的人看的**，不是写给评论者看的。

> **数据源**：Followin MCP 5 工具 — `metrics`（行情/宏观/基本面）· `news`（新闻/推文/TG）· `signal`（KOL 喊单/持仓/内部人）· `twitter`（原始 Twitter 操作）· `subscription`（自选盯盘）。tradfi 标的必传 `asset_type="tradfi"`；`news` 除看趋势外必带 `query`；`twitter` 全部走 `action` 路由。

## 0. 直接触发时的自检（本 Skill 可不经 `twitter-ops` 调度器）

⚠️ 用户可能直接说「今天该跟谁互动」而不走调度器，那边的初始化闸门**不会执行**。
开工前按 `config.md` §开工四检 逐条走一遍：

**① 账号锚定** = `ACCOUNT`（唯一权威，仍是占位符就停下来让用户填）
**② 目录** = `STATE_DIR`，🔴 不得指向 `/tmp`（硬检查）
**③ 时钟** 一律 shell 现取（`date +%F` / `date +%G-W%V`），全程复用同一组值，**不许凭模型的日期认知推算**
**④ 依赖文件「存在但仍是占位符 / 带 `INIT-STATUS: template-default`」= 视同未配置** → 记 `n/a` + 显式标注

🔴 **四条的完整判据与后果只维护在 `config.md` 一处，本文不复述**——
样板复制到七个文件会给人"全仓已覆盖"的错觉，而实际覆盖的只是最容易复制的那部分。

## 0.9 共用：扫描工具 + 筛选阈值

| 用途 | 调用写法 |
|---|---|
| 某账号最新推文 | `twitter(action="user_tweets", user_name="X", include_replies=false)` |
| 话题下高互动推文 | `twitter(action="search", query="关键词", query_type="Top")` |
| 按窗口精确搜 | `twitter(action="search", query="from:X", time_range="...")`（高频号翻页翻不到窗口起点时用）|
| 拉自己推文的评论 | `twitter(action="tweet_replies", tweet_id="...")`；`tweet_replies_v2` 是另一口径备选。🔴 **返回里会混入根推自身**（同 id、`isReply=false`）——按 `isReply` 或 id 剔掉，否则把原推算进评论、虚增计数 |
| 被 @ / 被提及 | `twitter(action="user_mentions", user_name="你的用户名")` |
| 评论者/KOL 影响力 | `twitter(action="user_info", user_name="X")`；批量用 `batch_user_info`，参数是 **`user_ids`（逗号分隔的数字 ID，不是用户名）** |
| 推文最新互动数 | `twitter(action="tweets_by_ids", tweet_ids="id1,id2")` |
| 关系与圈子 | `twitter(action="followers" / "followings" / "check_follow", user_name="X")` — 看对方最近在聊什么找切入点、看共同关注识别圈子 |
| 评论要引的数据 | 价格 `metrics(query="BTC price")` · 宏观 `metrics(query="US CPI latest")` · 链上快讯 `news(query="…")` · KOL 持仓 `signal(query="kol call trader position")` |

🚨 **数组参数全域禁用**：`keywords` / `categories` / `sources` 这类数组**即使主进程直调也会被序列化成字符串遭 schema 拒**（`["market"] has type "string"` 连环 `-32602`），**没有安全通道**。一律走 `query` 自然语言 / 空格拼串，服务端自解析。
🚨 **并发上限**：主进程一条 message 里 followin 调用 **≤4 个**（一次发 12 个会有半数 `-32001` 超时）。

⚠️ **`search` 和评论列表单次可返数万字符，必须走 Agent 子进程**，直接调会打爆上下文。
⚠️ **分页**：`user_tweets` / `tweet_replies` 首页只返最近约 20 条，覆盖一整天/一整周必须取 `next_cursor` 续调，直到最老一条早于窗口起点。**"他今天没发推"在翻页确认前不成立。**

### Outbound 目标筛选阈值

| 条件 | 为什么 |
|---|---|
| 发布 <2h | >4h 基本抢不到前排 |
| 已有 ≥50 互动 | 说明在起势，值得押 |
| 评论数 <100 | 评论区没饱和，你的评论还能被看见 |
| 作者粉丝 >10K | 曝光基数够 |
| 话题与你账号定位相关 | 不蹭无关热点 |
| 排序 | 有互动历史的 KOL > 同量级账号 > 遥不可及的大 V |

**扫描名单不写死在本文件**——填在 `references/kol-targets.md`（Tier 1/2/3 + 禁入互动池 + 准入硬规则）。第一次用先花 10 分钟把那张表换成你自己关注的账号。

## 1. Outbound（主动出击）

### 1.1 时间窗口决定出几条

| 发布时间 | 策略 | 条数 | 类型配比 |
|---|---|---|---|
| <30min | 🔴 抢位，速度第一 | 1 | 深度 ×1 |
| 30min–2h | 🟡 黄金窗口，质量+速度 | 3 | 深度/犀利/互动 各 1 |
| 2h–4h | 🟢 质量优先，多角度 | 5 | 深度 2 · 犀利 1 · 互动 1 · 幽默 1 |
| >4h | ⚪ 低价值，除非评论区起了新争议 | 0–1 | 视情况 |

紧急模式只出深度型——**深度型最容易换来原作者回复**，而原作者回复是这套打法里最值钱的东西。

### 1.2 动笔前先分析

原推核心观点（一句话）→ 作者定位（KOL/项目方/交易员/媒体）→ 评论区氛围（赞同/争议/嘲讽/求解释）→ 落在哪个时间窗口 → 你的切入机会（补数据/反面观点/深挖细节/幽默）。

### 1.3 四种评论写法

| 类型 | 什么时候用 | 硬要求 |
|---|---|---|
| 📊 深度见解 | 默认首选，尤其抢位模式 | 给出原推没有的视角或数据；逻辑链"观察→推理→结论"；2–4 句 |
| 🔥 犀利观点 | 现象明显、共识浮躁时 | 一句话立场清晰；可尖锐不可人身攻击；要有逻辑不能纯情绪 |
| 💬 互动引导 | 想换二次曝光时 | 以提问或半开放判断收尾，让人有回复欲 |
| 😤 幽默吐槽 | 补"活人感" | 1–2 句；可自嘲、嘲讽现象，不嘲讽个人；真的好笑才发 |

**句式模板全部在 `references/reply-strategies.md` §一 Outbound 主动评论模板**（每类 2–4 个填空句式 + KOL 帖下补数据 / 热门话题抢位两个即插即用模板）——写之前打开取，别现编。

数据优先复用上游热点采集已拉过的，只在缺口处回调 §0.9 的 MCP。

### 1.4 去 AI 味（每条必过）

像真人在认真回复而不是模板；不用"首先/其次/最后"编号；不出现"值得关注""不容忽视""总的来说"；长度自然（别每条一样长）；和原推直接相关而非泛泛而谈。

| ❌ AI 味 | ✅ 真人味 |
|---|---|
| 值得关注的是 / 不容忽视 | 有意思的是 / 关键在于 / 这个被低估了 |
| 总的来说 | 说白了 / 一句话 |
| 首先…其次…最后 | 直接说要点，不编号 |
| 这是一个很好的观点 / 我认为这非常重要 | （删掉，直接补充你的观点）/ 这才是重点 |

### 1.5 输出格式

```
🎯 @[用户名] | [X 分钟前] | 💬[评论] ❤️[点赞] 👁[浏览] | 窗口 [🔴/🟡/🟢] | 核心观点：[一句话]
📊 #1 [深度见解] ⭐首选   [评论内容]   → 策略：抢前排，展示专业度
🔥 #2 [犀利] / 💬 #3 [互动引导] / 😤 #4 [幽默]  …同上格式
📌 首选发布：#N（理由）｜最可能获回复：#N（理由）
```

**硬规则**：不发"👍""支持"这类零信息评论；引用转推必须带 ≥15 字点评。

## 2. Inbound（守自己评论区）

### 2.1 分级

| 层级 | 类型 | 策略 | 响应时间 |
|---|---|---|---|
| 🔴 S | 高质量质疑 / 有影响力账号的评论 | 必须认真回，展示专业 | 30 分钟内 |
| 🟠 A | 有深度的提问或补充 | 认真回 + 引发二次讨论 | 2 小时内 |
| 🟡 B | 可借势的评论 | 借势扩展，输出新观点 | 当日 |
| 🟢 C | 正面反馈 / 简单赞同 | 点赞或一两个字 | 当日，可批量 |
| ⚪ D | 无意义 / 广告 / 纯杠精 / **协同刷单簇** | 忽略（整簇一起判，不逐条）| 可不回 |

判 S 级要看评论者影响力（`user_info`）。**主推发出后 30 分钟内亲自回 2–3 条评论**——对话在算法里的权重远高于点赞，这是唯一能人为拉动的乘数。

### 2.2 S 级：高质量质疑

先判三件事：质疑者是谁（粉丝量/立场）、核心质疑点是什么、**你的推文是否真有漏洞**。然后四选一：

| 判断 | 策略 |
|---|---|
| 质疑合理 | **A. 承认 + 补充**——认下来，补新数据，公开修正结论 |
| 部分合理 | **B. 承认部分 + 坚持核心**——承认表述问题，核心逻辑用数据顶住 |
| 质疑不合理 | **C. 用数据反驳**——列两个指标 + 反推"若他成立则应出现 X，但没有"，结尾留不确定性 |
| 对方在抬杠 | **D. 冷处理**——"数据摆在那了，各人判断"，或只点赞不回复 |

四段可直接套用的回复脚本在 `references/reply-strategies.md` §二 S 级质疑。**用 C 之前必须用 §0.9 的 `metrics` / `news` / `signal` 把数字核到当下**，别用记忆里的价格。

### 2.3 A / B / C / D 级

- **🟠 A**：① 直接回答不废话 → ② 补一个对方没想到的角度 → ③ 用提问或半开放判断收尾。
- **🟡 B（最容易被忽视、运营价值最高的一层）**：评论本身一般，但能借势输出新内容——四种手法：引申 / 数据补充 / 预告下一条 / 抛给大家（句式见 reply-strategies §B 级借势）。
- **🟢 C**：点赞 /"谢了"/"认同"，别过度客套；对方是新粉可以多说一句。
- **⚪ D**：不喂养，人身攻击直接 mute/block。**例外**：杠精的观点如果围观者也在想，用数据回应**一次**——这一次是回给围观者的。
  🔴 **协同刷单簇整簇判 D**（实测：真实评论区最脏的一类）：多账号**近乎同模板** + 蹭原推喻体硬拐到**无关引流项目** + 短时间批量出现。这类 reply/like 恒为 0，§2.6 的 ratio 闸抓不到，只能靠内容模式认。识别后**整簇一起忽略、不逐条分析**，也别算进"评论区健康度"分母（否则会把广告刷屏误读成"负面舆情"）。

六个高频场景（被质疑数据准确性、被说马后炮、有人问操作建议、对方观点你不同意、新粉基础问题、被无理攻击）的成稿回复见 `references/reply-strategies.md` §场景化模板。

### 2.4 四种回复人设

🧊 **冷静分析师**（默认；应对质疑，数据说话不带情绪）｜🔥 **犀利交易员**（蠢问题/强观点，直接有力）｜🤝 **友好前辈**（新手提问，耐心简洁）｜😤 **段子手**（化解尴尬，自嘲、嘲讽现象）。按场景切换，用户也可指定。

### 2.5 输出运营方案

```
📋 分级总览：🔴 X | 🟠 X | 🟡 X | 🟢 X | ⚪ X
🔴 必须回复：@user "[摘要]" — 合理性：[判断] — 策略：[A/B/C/D] — 建议回复："[内容]"
🟠 建议回复 / 🟡 借势机会（同上格式，标出借势方向）
📊 健康度：正面/中性/负面 X%/X%/X%｜需否危机处理｜氛围：[健康/争议可控/需注意]
💡 下次发推优化建议：[一条]
```

### 2.6 ⚠️ spam 靶标：别把力气浇在沙子上

引流号会定向刷某几条推文的评论区，特征是**低赞高评**。

- **判据**：逐条算 `reply/like`，**>5 视为疑似靶标**（健康区 **<0.3**，口径与 performance-review / metrics-guide 一致；**账号级 >1.0 = 反常，报告要写「ER 不可采信」**）。用比值而非 replies 绝对数，正因为特征是"低赞"。
  🔴 **作用对象是「你自己的帖子」——判哪条帖被 spam 围攻，不是判单条评论**（实测教训：把 reply/like 套到单条评论上，分母恒为 0、闸全程失灵）。
- **处置**：靶标帖排在每轮巡检**最前**（不按浏览量排）——spam 最集中在这儿。
- **靶标 ≠ 内容失败**：靶标集中在中低量帖，**最大的爆款反而 ratio 最低**——spam 不随触达等比增长，更像定向骚扰。**别因为某条成了靶标就下调该类型内容配比。**
- **回复率目标按"去靶标"口径算**：评论区绝大部分是引流号时，追求"100% 回复率"没有意义。
- 🔴 **协同刷单簇：ratio 闸抓不到，得靠内容模式**（实测新增）。真实评论区最脏的不是"被围攻的靶标推"，而是**广告刷屏簇**——7+ 账号用近乎同一模板刷无关项目。这些评论**自己没人回复、reply/like=0**，从 ratio 闸底下完整逃逸。判据改用内容：**同模板 / 同引流项目 / 短时间批量 + 蹭原推喻体硬拐到无关标的 = 协同刷单**，整簇判 D 级忽略（见 §2.1）。
- ⛔ 本 Skill 只做优先级排序和口径修正，**不做删除/举报/拉黑**——不可逆动作交人工。
- ⚠️ **"评论体拉不出来 = 折叠"这个推断不安全**（实测修正）：`tweet_replies` 单页约 20 条、`has_next_page` 持续供货，返回数 < `replyCount` **多半只是分页没翻完**（实测 30<58 时 `has_next_page` 仍 true）。**只有翻到 `has_next_page=false` 仍显著少于 `replyCount`，才可判折叠降权区存在**；没翻到尽头就下"折叠"结论会把普通分页误报成降权。

## 3. 规划与追踪

### 3.1 今日互动预算

| 日类型 | Outbound 评论 | Inbound 回复 | 主动发推 |
|---|---|---|---|
| 热点日（有大事件）| 3–5 条 | 全部 S/A 级 | 2–3 条 |
| 普通日 | 5–8 条 | S/A/B 级 | 1–2 条 |
| 低谷日（无热点）| 8–10 条 | 全级别 | 0–1 条 |

**热点日守、低谷日攻**：有热点时自己的推文就是流量入口，精力放内容；没热点时主动出击找曝光。日内三段节奏见 `references/reply-strategies.md` §三。

### 3.2 KOL 关系分层与每周 KPI

🟢 **已建立**（对方互动过你 ≥3 次）→ 维护，定期互动，可以 @ 对方讨论｜🟡 **认识中**（1–2 次）→ 继续高质量评论加深印象｜⚪ **未接触** → 通过 Outbound 在其推文下反复出现。

每周核对：主动评论/引用 ≥15 条 ｜ Tier 1 名单**每人**至少 1 次有效互动 ｜ 与 ≥3 个「已建立」互动、≥5 个「认识中」推文下评论、接触 ≥2 个「未接触」｜ 检查有没有新 KOL 关注了你（要及时回应）｜ 被回复/被引用次数单独记（影响力指标）。

### 3.3 效果追踪

Outbound 只追四件事：哪条换来了**原作者回复**（最高价值）、哪条点赞最多、在谁的推文下效果最好（下次优先）、哪种类型转化最好。粉丝增长归因只能是推测性的（发推日 vs 非发推日、有无 Outbound 的日增量、被大号互动后的跳变），别当精确数。账号级复盘交给 performance-review。

## 关键原则

- **规划先行**：先花 5 分钟定今天评谁、守哪条，不要盲目刷。
- **质量 > 数量**：3 条有深度的评论 > 10 条水评；**速度 > 完美**：<30min 的推文出 1 条就发。
- **回复是给围观者看的**：说服不了质疑者，但围观的人在看你怎么应对。**超过两轮的争论立即撤。**
- **关系是资产**：KOL 关系靠长期积累；带数字的专业补充比"大佬说得对"有用 100 倍。
