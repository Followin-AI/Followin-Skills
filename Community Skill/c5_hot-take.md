# c5 热点扫描+速报+财报速读——两步交互（事件驱动，随时触发）

本 skill 仅供社群运营人员触发使用（群成员不直接交互），随时触发，不设固定档期。定位：承接对方原始诉求里"大事件下来时重点影响的标的"，是全 bundle 事件驱动能力的主要承载模块。运营任意时刻说"扫一下热点"，走两步交互：第一步输出热点扫描菜单（见第 1 节），每条候选自带出稿建议三档；第二步对选中的条目成稿（见第 2 节），产出 300-500 字速报贴。若识别到财报事件，第二步改走第 3 节的专用速读路径，产出固定四句结构。

若触发时带 frontmatter args `topic_or_ticker` 直接点名（如"就 NBIS 出一篇""XX 财报出来了"），跳过第一步扫描，直接进入第二步成稿；触发短语含"财报"关键词，或运营是从 c6 标的速查的"🔥 值得速报"建议衔接过来，同样按点名路径处理，并按第 3 节的识别规则路由到财报速读子型（而不是第 2 节的常规速报模板）。

## 1. 第一步 · 扫描（热点扫描菜单）

### 1.1 调用序列（≈2 点）

调用序列：

| 步骤 | 调用 | 额度 |
|---|---|---|
| 1 | `news(空 query, asset_type="tradfi", time_range="24h")` 趋势榜（hot 排序，实测 sort_by_effective="hot"） | 0（4h 窗口不可用，见下） |
| 1b | 对每条候选 `news(query="<核心名词1> <核心名词2>", time_range="24h", sort_by="relevance", verbosity="concise")`（搜索模式，**不传 asset_type**，见第 2 节步骤 3；**必须按 relevance 排**，理由见下方调用示例），用返回行的 `source_url` 域名数判断"多源"、用最早确认报道的 `published_ts` 判断是否在时效窗口内（上一个美股常规收盘之后，见第 4 节 age gate）；`time_range` 要盖住上一个常规收盘：平日 24h，跨周末 / 休市时按 c1 第 2 节窗口口径放宽到 72h / 96h | 0 |
| 1c | 菜单候选 ≤5 只批量 `metrics(keywords=["<T1>",…], query="行情", categories=["market"], asset_type="tradfi")` 取菜单里写的涨跌幅；不调则菜单不写涨跌幅 | 1 |
| 2 | `signal(categories=["kol_call"], query="consensus", asset_type="tradfi", time_range="24h")` 喊单热度佐证 | 1 |

步骤 1 不能短于 24h：2026-07-22 实测 4h 返回 0 篇（`meta.warnings` 报 `asset_type_filter_emptied`，候选池太小被 tradfi 过滤器清空）。时效窗口起点是上一个美股常规收盘（第 4 节 age gate），跨周末 / 休市时 24h 盖不住，步骤 1 与 1b 一起按 c1 第 2 节窗口口径放宽到 72h / 96h。这与 N-10（`metrics()` 的 `time_range <1d` 返一个月前旧数据）是两回事，不要混为一谈。

**趋势池很小，且趋势榜行不能直接当判据（2026-10-05 实测，2026-10-08 复测）**：tradfi 24h 只返回 3-5 个话题（10-05 为 3 个、10-08 为 5 个），`limit=30` 也不变，"按 `published_ts` 取最近"在这个规模下没有意义；趋势榜每个话题只有一条 AI 摘要，**没有 `source_url`**，判断不了信源是否独立；行上的 `published_ts` 是话题刷新时间，不是事件时间（10-05 实测两条不同话题的时间戳相同到毫秒；10-08 实测中东油价话题行显示 5.5 小时前，搜索到的最早确认报道在 15.1 小时前）。所以"多源""≤12h"一律靠步骤 1b 判，**不跑 1b 的候选只能标 📌 或 🚫，不能标 🔥**。

步骤 1 的 asset_type 例外依据（N-1）：

> N-1：news 趋势模式（空 query）传 asset_type="tradfi" 可用且 0 额度；实体搜索亦 0 额度（实测）。搜索模式**不传 asset_type**：2026-10-05 实测传 tradfi 召回下降（PTC 8→2、MU 20→17）且挡不住加密噪音（N-145），只在趋势模式传。

调用形态铁律（本序列全程通用）：

> **调用形态（2026-10-01 实测，取代 2026-07-20 的"数组被拒、只能 query 串"铁律）**：入参分工是 **`keywords` 数组放标的、`query` 放意图词、`categories` 指定类别**。`signal` 必须显式传 `categories`。每次调用最多 5 个 keywords，超出或解析不了的项写在 `meta.warnings`（`keyword_count_over_max` / `kw_not_canonical`），**调用后读一遍**，缺的分批补。单批并行 ≤4 路（SSE 红线）。客户端不接受数组入参（报 `-32602`）时，美股代码可退回 query 空格拼串（实测仍能解析），商品代码（`*USD`）没有可用的 query 串写法。另：Followin session 每 5-8 次调用可能短挂，重试 1 次即恢复，还不行让运营 `/mcp restart followin`。

每步 query 主形态调用示例：

```
1. news(query="", asset_type="tradfi", time_range="24h")
   # 趋势模式，quota=0；4h/1h 短窗口不可用（2026-07-22 实测 0 篇，asset_type_filter_emptied），固定用 24h
   # content 是 AI 摘要，只作选题；摘要里的数字常自相矛盾（2026-10-05 实测），事实与数字一律取 1b 的原文

1b. news(query="<核心名词1> <核心名词2>", time_range="24h", sort_by="relevance", verbosity="concise")
   # 每条候选一次，quota=0；不传 asset_type（理由见第 2 节步骤 3）
   # 多源 = 不同 source_url 域名 ≥2；时效 = 最早一条确认报道的 published_ts（传闻阶段 "nears deal / source says" 不算确认）
   # 必须 sort_by="relevance"：默认按时间倒序，热门事件一页全是最近几小时的跟进稿，页内最早一条不是事件最早报道。
   #   2026-10-08 实测中东油价：默认排序页内最早 3.1 小时前（limit=30 也只到 6.6 小时前），会把陈货误判成新鲜；
   #   relevance 排序首条就是路透「胡塞称袭击利雅得机场」15.1 小时前、「白宫要五角大楼备打击伊朗方案」18.4 小时前
   # 核心名词用公司全名 / 专有名词，不要带常见词：2026-10-08 实测 "Webull House committee" 的 House 召回一页美国中期选举和房价新闻
   # 页内仍是零星跟进稿、看不到首发的，读正文里的日期（"said on Thursday" / "6 日至 7 日"）再判，判不了按过时效处理

1c. metrics(keywords=["<T1>","<T2>",…], query="行情", categories=["market"], asset_type="tradfi")
   # 菜单候选 ≤5 只一批；涨跌幅自算 change ÷ previousClose × 100，盘前/盘后写法见第 2 节步骤 4

2. signal(categories=["kol_call"], query="consensus", asset_type="tradfi", time_range="24h")
   # 喊单聚合（总帖数 / 多空比 / top_calls），1 额度；此处只用喊单热度佐证扫描菜单排序，不做温度计钻取
```

### 1.2 输出格式：热点扫描菜单（T-3，逐字收录）

按"非专业运营 10 秒决策"设计，每条候选自带出稿建议，格式固定（T-3 样例，2026-07-22 已核可，逐字收录）：

```
🔍 熱點掃描 7/22 16:40（台北，截至此刻）
1️⃣ 輝達披露持股 Nebius 9.3%｜NBIS +17%、AI 算力鏈聯動
   → 🔥 建議速報：事件重大、標的明確、還在發酵中
2️⃣ 存儲板塊集體反彈｜SNDK +13%、MU 推特 9 帖全多
   → 📌 建議並回早報/溫度計：板塊行情，適合彙總視角
3️⃣ 某小盤股單日 +40%｜無新聞無研報覆蓋
   → 🚫 建議忽略：無敘事層，蹭了容易帶新手追高
（回覆編號出稿，或直接說「就 NBIS 出一篇」）
```

排版规则同全 bundle：纯文字＋emoji，不套 markdown 加粗/标题/表格，层级靠 emoji ＋ 空行 ＋「｜」（S-9 镜像）。运营回复编号即触发第 2 节成稿；也可以跳过菜单直接说"就 NBIS 出一篇"，效果等同选中对应候选。

菜单里的涨跌幅只能来自步骤 1c 的返回值（铁律 2），没跑 1c 就不写涨跌幅。候选不足 2 条时，可从步骤 2 的 `top_calls` 补 1 条（仅能标 📌）；没有任何一条够得上 🔥 时，菜单首行写「今日平靜，暫無建議速報事件」（铁律 3），不硬凑。

**菜单末尾的内部备注（2026-10-08 用户拍板，T-3 样例不含这一行）**：每次扫描在「（回覆編號出稿…）」之后另起一行，列出因过时效被挡掉的候选，供运营决定要不要否决。只给运营看，**不进对外贴文**，不计入菜单条数。格式固定：

```
（內部｜已過時效未列：PENG 財報（10/7 美東 12:02）、Webull 國安風險（10/7 美東 12:24）；時效起點＝10/7 美東 16:00 收盤）
```

每条写「主题（最新進展 M/D 美東 HH:MM）」，时间取该事件计时用的那条确认报道的 `published_ts`（多日事件取最新一轮新事实，单次事件省略「最新進展」四字）；末尾写本次的时效起点。没有被挡掉的条目时写「（內部｜已過時效未列：無）」。无美股传导的外国个股不写进这一行（第 1.3 节）。

### 1.3 出稿建议三档判据（写死在 skill，判断责任在 skill 不在运营）

> 出稿建议三档判据写死在 skill：🔥速报（事件驱动+标的明确+时效内+多源）/ 📌并回定期栏目（板块级、慢发酵）/ 🚫忽略（纯交易噪音、单源未证；过时效的陈货、无美股传导的外国个股不入菜单）。运营可否决建议，但 skill 必须给出立场——判断责任在 skill 不在运营。

三档判据逐条展开：

- **🔥 建议速报**：四个条件同时满足才算——事件驱动（有具体催化：披露/公告/数据/突发新闻，不是纯价格波动）+ 标的明确（能指认 1-2 个直接受影响的标的，不是"大盘情绪"这种空泛描述）+ 时效内（步骤 1b 返回里该事件**最早一条确认报道**的 `published_ts` 晚于上一个美股常规收盘（美东 16:00）；持续多日的事件按最新一轮新事实计时；不用趋势榜行的 `published_ts`，口径见第 4 节 age gate）+ 多源（步骤 1b 返回里 ≥2 个不同 `source_url` 域名相互印证；公司正式公告（GlobeNewswire / BusinessWire / 8-K）＋ 步骤 1c 已核实的价格反应，视同满足"多源"。公司公告也不受本节下方"单源 BREAKING"规则约束——那条规则专门针对地缘/政策/监管类传闻，两者是不同情形，不要混淆）。不跑步骤 1b 的候选不能标 🔥。
- **📌 建议并回定期栏目**：板块级、慢发酵——多个标的同涨同跌，但找不到单一标的的清晰催化事件，适合汇总进下一次早报或温度计，而不是单独出一篇速报。海外指数类宏观条目（日经、KOSPI、欧股大跌等）且无直接受影响的美股，同样标 📌，并回早报「大盤一眼」。**外国个股（外国正股）且无直接受影响的美股不进菜单**，也不写进「已過時效未列」备注（2026-10-08 用户拍板；例：江淮汽车 600418.SS 刹车测试跌停，与美股无传导）。外国个股能指认直接受影响的美股的（如三星财报 → MU / SNDK），按美股标的照常判三档。
- **🚫 建议忽略**：只用于两种情形——纯交易噪音（无叙事层的爆仓/大单/技术位突破）、单源未证（只有一条来源且无法核实）。这两类在菜单中保留并标 🚫，以示 skill 立场。**过时效的陈货不入菜单**，只记进菜单末尾的「已過時效未列」内部备注（见第 1.2 节、第 4 节 age gate）。

判断责任句：运营可以否决 skill 给出的建议（比如运营判断第 3 条其实值得写），但 skill 必须先给出自己的立场再交给运营决定，不能只列数据不表态——判断责任在 skill 不在运营，这个原则同样是 c6 标的速查"出内容建议"收尾设计的共同依据。

## 2. 第二步 · 成稿（速报贴文）

### 2.1 调用序列（≈1-2 点）

调用序列：

| 步骤 | 调用 | 额度 |
|---|---|---|
| 3 | `news(query="<核心名词×2>", time_range="24h")` 补事件细节与推特层原文（**不传 asset_type**） | 0（实测） |
| 4 | 受影响标的 ≤5 一批 `metrics(keywords=["<T1>","<T2>",…], query="行情", categories=["market"], asset_type="tradfi")` 实时快照（含盘前盘后价） | 1 |
| 5 | （可选，重大事件；并购 / 临床数据类事件跳过）`signal(keywords=["<TICKER>"], categories=["kol_call","insider_trading","institutional","trader_position"], asset_type="tradfi")` 或研报钻取加一层深度 | 1-2 |

若触发时带 args `topic_or_ticker` 或从菜单选中编号，第 3 步的"核心名词×2"直接取自选中话题/标的名，跳过第 1 节的步骤 1、1b、1c、2（从菜单选中时，1b / 1c 的返回可直接复用）。

调用形态同第 1 节（本序列同样全程适用）：

> **调用形态（2026-10-01 实测，取代 2026-07-20 的"数组被拒、只能 query 串"铁律）**：入参分工是 **`keywords` 数组放标的、`query` 放意图词、`categories` 指定类别**。`signal` 必须显式传 `categories`。每次调用最多 5 个 keywords，超出或解析不了的项写在 `meta.warnings`（`keyword_count_over_max` / `kw_not_canonical`），**调用后读一遍**，缺的分批补。单批并行 ≤4 路（SSE 红线）。客户端不接受数组入参（报 `-32602`）时，美股代码可退回 query 空格拼串（实测仍能解析），商品代码（`*USD`）没有可用的 query 串写法。另：Followin session 每 5-8 次调用可能短挂，重试 1 次即恢复，还不行让运营 `/mcp restart followin`。

每步 query 主形态调用示例：

```
3. news(query="<核心名词1> <核心名词2>", time_range="24h")
   # 搜索模式，quota=0（实测）；核心名词直接取自菜单条目或点名内容；要权威报道可加 sort_by="relevance"
   # 搜索模式不传 asset_type：2026-10-05 实测同一 query 传 tradfi 召回从 8 条降到 2 条，路透 / 彭博 / WSJ 全部丢失且无 warning；asset_type 只在第 1 步趋势榜用

4. metrics(keywords=["<TICKER1>","<TICKER2>",…], query="行情", categories=["market"], asset_type="tradfi")
   # 受影响标的批量快照；每批 ≤5，超出的写在 meta.warnings（keyword_count_over_max），分批补跑
   # 一律加 categories=["market"]：只写 query="行情" 时是否附带基本面块不稳定（同 c1 调用形态铁律）
   # 快照没有涨跌幅字段，自算 change ÷ previousClose × 100；非交易时段返回的是上一常规收盘，标「最近收盤」：有 _quote_session 按它判；没有（^VIX、商品、多数小盘股，N-139）看 as_of，不在美东 9:30–16:00 内都算最近收盘
   # 盘中（美东 9:30–16:00）price 就是实时成交价，按 as_of 标「截至 美東 HH:MM」；2026-10-08 实测美东 10:10 取数，XOM / CVX / UAL / DAL / SPY 都没有 _quote_session，也都没有 extendedHoursQuote（盘中不返这个字段，不是缺失）
   # 盘前/盘后：extendedHoursQuote 只有 bid/ask（无成交价、无涨跌字段），用 (bid+ask)/2 对比 price（上一常规收盘）自算，标「盤前報價約」/「盤後報價約」
   # 该字段可能整个缺失（2026-10-05 实测事件主角 PTC 连续 3 次缺失，同批 ADSK / PCVX 有）——缺失时只写「最近收盤 X」＋「本次未取得盤前報價，媒體稱…，以開盤實際報價為準」，不引用新闻里的百分比当数字
   # 外国公司用主挂牌代码（如 keywords=["SU.PA"]），OTC ADR 只作补充：2026-10-05 实测 SBGSY 停在上周五 +3.65%，同时 SU.PA 当天 −9.9%，方向相反
   # 原油 / 黄金等商品只能走数组：keywords=["CLUSD","BZUSD","GCUSD"]（写进 query 串整批返空）

5. signal(keywords=["<TICKER>"], categories=["kol_call","insider_trading","institutional","trader_position"], asset_type="tradfi")
   # 可选，重大事件才加：喊单/实盘/内部人四维钻取深度（做法同 c4 步骤 2）；不带 time_range，kol_call 行按 symbol 自行筛
   # 并购 / 临床数据类事件跳过：2026-10-05 实测并购标的 PTC 四类里喊单、实盘整类不返回，内部人只有豁免 / 代扣行和滞后的议员卖出，13F 停在上季末，白花 1 点
   # 或改走研报深度：metrics(keywords=["<TICKER>"], query="research reports", verbosity="detail", time_range="7d", asset_type="tradfi")（做法同 c3 步骤 2）
```

### 2.2 产出模板：速报体（300-500 字）

> 产出结构（速报体，300-500 字，比早报短）：**發生了什麼**（两句）→ **誰受影響**（标的 + 实时价 + 一句传导逻辑）→ **市場怎麼解讀**（多空各一句，来源标注推特/媒体）→ **接下來看什麼** → 免责声明（名词卡可选）。

落地结构：

1. **标题**：📌 + 速報 + 事件主题
2. **一句話先懂**（≤40 字）
3. **模块正文**，四小节：
   - **發生了什麼**：两句话交代事件本身；持续多日的事件，第一句以「最新進展：」开头写计时用的那一轮新事实，背景放第二句（第 4 节 age gate）
   - **誰受影響**：标的代码 + 本次调用返回的实时价（含涨跌幅）+ 截至时间戳（"截至 XX:XX"，呼应 S-7 铁律 5）+ 一句传导逻辑（为什么这个事件会影响这个标的）；盘前报价缺失时的写法见步骤 4 注释
   - **市場怎麼解讀**：多方一句 + 空方一句，各自标注来源（推特/媒体），呼应 S-5 多空平衡，不能只放一边
   - **接下來看什麼**：一个可验证的前瞻观察点
4. 今日名詞卡（可选——c5 速报单篇 300-500 字，比早报/研究笔记短得多，S-10"每篇一张"的默认强制在本模块放宽为"有合适术语才加"，没有就跳过，不必为了凑名词卡硬找一个）
5. 免责声明（S-11 对外版，逐字，必须）
6. 互动钩子（可选，S-3 第 7 段镜像，仅当天尚未用过额度时才加——见第 5 节的跨模块共享说明）

字数按 S-4 镜像：c5 速报 300-500 字，比早报短，四小节尽量各一到两句说完，不铺陈。字数按正文（标题至「接下來看什麼」）计，不含名词卡与免责。

以下是结构示范样例（非实测数据，实现时按当次调用返回替换；排版规则不变——纯文字＋emoji，不套 markdown 加粗/标题/表格，层级靠 emoji ＋ 空行 ＋「｜」——S-9 镜像）：

```

一句話先懂：輝達揭露已持有 AI 算力公司 Nebius 9.3% 股份，NBIS 應聲大漲，AI 算力鏈跟著沸騰。
```

## 3. 财报速读子型（财报季日常）

> **财报速读子型（财报季日常）**：菜单或运营点名识别到财报事件（"XX 财报出来了"）→ 走专用成稿路径：`metrics(keywords=["<TICKER>"], query="财报 分析师评级", asset_type="tradfi")`（≈1 点）→ 速读贴固定四句结构：**營收/EPS 超或不及预期（具体数字 vs 预期）→ 指引怎么说 → 盘后股价反应 → 下一个观察点**。财报密集周这是 c5 的主要形态。

识别规则：触发短语含"财报"关键词（如"XX 财报出来了"），或第 1 节扫描菜单里某条候选本身就是财报事件，或运营从 c6 标的速查"🔥 值得速报"衔接过来且该标的当日有财报——三种情形都路由到本节的专用速读路径，不走第 2 节的常规速报模板。

调用（2026-10-01 实测）：ticker 放 `keywords`，`query` 只放中文意图词。**不要**把 ticker 和英文意图词一起塞进 query 串——`query="<TICKER> earnings beat miss analyst ratings"` 实测仍把 "beat" 当成 ticker（`keywords=["NVDA","BEAT"]`，N-14 未修）。

```
metrics(keywords=["<TICKER>"], query="财报 分析师评级", asset_type="tradfi")
# 返回：fiscal_quarters[0]（earnings_surprise + financial_statement）/ consensus_price / next_earnings_estimate / analyst_grades / analyst_estimates / eps_trend
# 要盘后快照另调：metrics(keywords=["<TICKER>"], query="行情", categories=["market"], asset_type="tradfi")
```

**字段名已换代（N-109）**：旧的 `beat_miss` / `latest_quarter` 两个 block 已不存在。超预期数据在 `fiscal_quarters[0].earnings_surprise`（`actual_eps` / `estimated_eps` / `eps_surprise_pct` / `actual_revenue` / `estimated_revenue` / `revenue_surprise_pct` / `report_date`），财报本身在 `fiscal_quarters[0].financial_statement`（`revenue` / `eps` / `netIncome` / `period_end`）。只返最新一季。≈1 点。

**财报当晚的数据时差（2026-07-23 实跑发现，2026-10-01 复测仍在，必读）**：财报公布当晚，`fiscal_quarters[0]` 可能还停在**上一季**，或者**只更新了一半**——实测 MU 9/30 盘后发财报，10/1 查到的 `fiscal_quarters[0]` 已有新一季的 `financial_statement`（营收 / EPS），但**整个 `earnings_surprise` 缺失**（没有预期值，算不出超预期幅度）。因此四句结构里的"本季实际 vs 预期"**当晚从第 2 节步骤 3 的 `news()` 返回里取**（媒体与公司披露原文，0 额度），或用市场级日历 `metrics(query="earnings calendar", asset_type="tradfi", date_from, date_to)`（不传 `country`：它按注册地过滤，会漏掉外国注册的美股，N-133；客户端只留 `^[A-Z]{1,5}$` 代码）里该公司那一行的 `epsActual` / `epsEstimated` / `revenueActual` / `revenueEstimated` 自算；写之前先核对 `earnings_surprise.report_date` 是不是本次财报日，不是就不能当本季数字用。

速读贴固定四句结构，逐条展开：

1. **营收/EPS**：本季实际营收与每股盈余，对比市场预期，写出具体数字（不能只写"超预期"三个字，必须是"实际 X vs 预期 Y"这种可回溯的数字对比，价格与财务数字只能引用本次调用返回值，呼应 S-7 铁律 2）；当晚数据源见上方"财报当晚的数据时差"——取 `news()` 返回的媒体/披露原文，不取未更新的 `earnings_surprise`。另：**EPS 若含一次性项目必须点破**（实测 GOOGL Q2 每股获利 9.11 美元 vs 预期 2.89 美元，但其中约 990 亿美元来自一次性项目，直接写"超预期 3 倍"会严重误导新手）——凡实际 EPS 与预期偏离幅度异常（>50%），先在 news 层确认是否有一次性损益，再决定怎么写。
2. **指引**：管理层对下一季或全年营收/获利的预测怎么说——上调、维持还是下调。
3. **盘后反应**：财报公布后股价的实际反应，必须是本次调用返回的快照数据，按财报公布的实际时段标注「盤中」或「盤後」。
4. **下一个观察点**：一个可验证的前瞻点，比如下一季财报会不会延续这次的指引基调。

字数：S-4 未单列财报速读的字数上限——四句结构本身比常规速报更精简，通常远短于 300-500 字区间，按四句结构的精简本质自然收在更短篇幅即可，不必刻意注水凑字数。名词卡与互动钩子默认不加（四句结构篇幅太短，硬加反而破坏"速读"的紧凑感）；免责声明仍是必须项，不因篇幅短而省略。

以下是结构示范样例（非实测数据，实现时按当次调用返回替换；排版规则同上）：

```
📌 財報速讀｜GM 通用汽車

營收/EPS：本季營收與每股獲利均優於市場預期（實際數字以本次調用回傳為準）。

指引：管理層上調全年財測，對下半年需求維持樂觀。

盤中反應：消息公布後盤中一度上漲 3.6%（實際漲跌以本次調用回傳快照為準）。

下一個觀察點：留意下一季財報會不會延續這次上調指引的樂觀基調，以及下次法說會的美東/台北雙時區排程。

⚠️ 以上整理自公開研報與市場數據，僅做資訊分享，不構成投資建議。
```

## 4. 防坑规则（镜像）

> 防坑规则：
> - 继承 c1 全部过滤规则（代币化股票/加密噪音/杠杆 ETF）。
> - 速报时效红线（age gate，借鉴 trend-scout §5.0）：趋势榜按热度返回、常混多日陈货，**必须机器核每条候选的事件时间**（步骤 1b 最早确认报道的 `published_ts`；早于上一个美股常规收盘（美东 16:00）的不得入"实时"菜单；持续多日的事件按最新一轮新事实计时），禁止肉眼估。所有引用行情必须是本次调用返回值并标注时间戳（"截至 XX:XX"）。
> - 单源 BREAKING：地缘/政策/监管类事件 ≥2 独立信源才可当事实写，否则标"消息尚待確認"（风格 SSOT 单源铁律）。
> - 纯交易事件不成稿：单一爆仓/大单/技术位突破且无叙事层（政策锚/产业链传导/跨源共振）的条目入菜单时一律标 🚫——对新手社群是噪音不是内容。
> - 趋势榜摘要不可引用：趋势榜 `content` 是 AI 摘要，只作选题，事实与数字一律取步骤 1b / 3 的原文。
> - 单事件单贴：一次速报只写一个热点，多个热点让运营分次选，避免大杂烩。

逐条展开：

- **继承 c1 过滤规则**：继承 c1 第 4 节「异动榜过滤」与「代币化+加密噪音白名单剔除」两条，原文以 c1 为准，本节不另抄关键词表。在 c5 里，前者用于步骤 1c / 步骤 4 批量快照涉及的候选，后者用于步骤 1 趋势榜（实测混入代币化股票与加密资产，剔除后不进热点菜单）。

- **速报时效红线（age gate，S-7 铁律 5 的强化版）**：c5 定位是"实时"热点，趋势榜按热度排序返回、常混多日陈货——混入一条几天前的陈货并当"刚发生"来写，是对新手社群的信任伤害，因此本模块把铁律 5 加严为机器核规则：
  - **趋势榜行的 `published_ts` 是话题刷新时间，不是事件时间**（2026-10-05 实测：PTC 与 PCVX 两条话题时间戳相同到毫秒，都显示 0.05 小时前；实际 FT 传闻在 15.8 小时前、路透确认在 6.0 小时前、Vaxcyte 公告在 1.3 小时前）。时效一律取步骤 1b 搜索返回里**该事件最早一条确认报道**的 `published_ts`；传闻阶段（"nears deal / source says"）与确认阶段分开计时，以确认报道为准。1b 必须按 `sort_by="relevance"` 取——默认按时间倒序时，热门事件整页都是最近几小时的跟进稿，页内最早一条会把陈货误判成新事件（2026-10-08 实测，见第 1 节步骤 1b 注释）。
  - **时效窗口＝上一个美股常规收盘（美东 16:00）之后**（2026-10-08 用户拍板，取代原固定 12 小时）：美东 16:00 换成 UTC 是夏令时 20:00Z、冬令时 21:00Z；"上一个常规收盘"取当前时刻之前最近的一个美股交易日 16:00——盘中跑取前一交易日收盘，美东 16:00 之后跑取当天收盘（当天盘中的事件已被当天收盘价消化，按过时效处理），周末 / 休市取最后一个交易日收盘。这样亚洲盘隔夜事件（如韩、台、日企业盘后公布的财报）能进菜单——原 12 小时闸会把它们挡在美股开盘前后之外（2026-10-08 实测：三星初估财报首发在美东 10/7 22:09，台北 10/8 22:10 扫描时已过 12 小时，按收盘锚则在 10/7 16:00 之后、算新鲜）。
  - **持续多日的事件按最新一轮新进展计时**（2026-10-08 用户拍板）：先用 1b 判断是不是多日事件（relevance 排序的首发早于时效窗口），是的话找最近一轮**新事实**——新的袭击、新的官方表态 / 声明、新的数据 / 公告；跟进评论、分析、复述旧事实都不算——以这一轮新事实的最早确认报道计时。找不到窗口内的新事实、只有价格在动的，按过时效处理。成稿时「發生了什麼」第一句写「最新進展：」（见第 2.2 节）。
  - 扫描菜单的每一条候选，必须机器核对上述事件时间，拿它和时效窗口起点（上一个常规收盘换成的 UTC 时间戳）做比较——不是"读一眼发布时间字符串觉得看起来很新"这种肉眼估算。
  - 早于时效窗口起点的条目一律不得列入热点菜单，无论其热度分数或喊单量看起来多高；只记进菜单末尾的「已過時效未列」内部备注。
  - 禁止肉眼估：不能凭"这条新闻感觉是今天的"这种主观印象判断，任何进入菜单的条目都必须能够回答"最早确认报道（多日事件取最新一轮新事实）的 `published_ts` 是几点、上一个常规收盘是几点"这个具体问题。
  - 所有第二步成稿引用的行情数据，必须是本次调用（步骤 3-5）返回值，并在贴文里标注"截至 XX:XX"时间戳（S-7 铁律 5 原文：铁律5 时效：引用行情标「截至 XX:XX」；>12h 旧闻不得当"实时热点"）。c5 菜单的"实时"口径以本节收盘锚为准，铁律 5 里的 12h 在 c5 不再单独套用。

- **单源 BREAKING（S-7 铁律 1）**：地缘/政策/监管类事件 ≥2 独立信源才可当事实写，否则标「消息尚待確認」。这是 c5 最容易触发本规则的场景——热点事件常常第一时间只有一条信源。若扫描菜单或成稿阶段判断某条属于地缘/政策/监管类，且当前只有单一信源，必须在贴文里明确标注「消息尚待確認」，不能因为"热点很吸引人"就当既成事实处理。

- **纯交易事件不成稿**：单一爆仓/大单/技术位突破且无叙事层（政策锚/产业链传导/跨源共振）的条目入菜单时一律标 🚫——对新手社群是噪音不是内容。这条规则直接决定扫描菜单第一步的候选池：某标的当日波动很大，但如果找不到对应的"为什么"（没有政策锚点、没有产业链传导逻辑、没有跨源数据共振），即使波动幅度惊人（如 T-3 样例第 3️⃣ 条"某小盤股單日 +40%"），也只能标🚫忽略，不能列入值得出稿的候选。

- **单事件单贴**：一次速报只写一个热点，多个热点让运营分次选，避免大杂烩。第二步成稿阶段，运营从菜单选中一个编号（或点名一个话题/标的）后，本次产出只针对这一个事件展开，不会把菜单里其他几条也顺带塞进同一篇贴文。运营如果想连续出稿多个热点，需要逐条分别触发第二步，各自产出独立的一篇贴文。

## 5. 发前自检 + 互动钩子额度 + 额度哨兵

S-12 清单（逐字，每篇产出前逐项过）：

> 繁体✓ 大白话✓ 字数✓ 名词卡✓ 免责✓ 多空平衡✓ 单源标注✓ 价格可回溯✓

c5 专属追加两项：
- **时效可回溯✓**：菜单每条候选的事件时间（步骤 1b 最早确认报道的 `published_ts`，多日事件取最新一轮新事实）与上一个美股常规收盘的比对结果、以及成稿引用的"截至 XX:XX"时间戳，都能指向本次调用返回值，不是凭印象判断。
- **单事件单贴✓**：确认本次产出只写了一个热点，没有把菜单里其他候选也夹带进同一篇贴文。

互动钩子共享额度（S-3 第 7 段镜像）：

> 只出现在 c1/c5、一天最多一次、问题无立场不诱导买卖方向、c3/c4 严肃内容不加。

S-3 把 c1/c5 并列在同一条"一天最多一次"的约束下，两个模块共享同一份当日额度：当天不论是 c1 的任何产出，还是 c5 当天已出过的任意一篇速报，只要其中任何一篇已经用掉一次互动钩子，当天剩余所有产出（不分 c1 还是 c5）都不再添加。c5 是事件驱动模块，同一天可能触发多次，尤其需要留意这一点——不能因为"这是 c5 今天第一次出稿"就默认可以加钩子，还要倒查当天 c1 是否已经用过；skill 拿不到当天其他产出的状态，**无法确认当日额度时默认不加**，由运营自行补。财报速读子型固定四句结构，不含互动钩子这一段，不占用该额度。

额度哨兵（内部提醒，不进对外贴文，设计文档对应章节）：

> **额度哨兵**：每次模块跑完读一次 `meta.quota`（每个返回都带，实测），`remaining/limit < 15%` 时在产出末尾附一行内部提醒（不进对外贴文）："⚠️ 本月額度剩 N 次，按當前節奏約可跑 X 天，考慮降頻或升級"。额度见底导致日更断档比任何单篇内容缺失都伤运营。

本模块因随时触发、单日可能多次运行，额度哨兵检查应在每次单独触发（无论是第一步扫描还是第二步成稿）跑完后都执行一次，不要因为"今天已经检查过"而跳过——事件驱动模块的额度消耗节奏和早报/周报固定档期完全不同，需要更频繁的自我检查。
