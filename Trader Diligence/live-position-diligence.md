> ⑦ 按显示名分组，看有没有**同名但 profile 指纹不同**的两行 → 有 = N-59s 仍在（**别当渲染重复合掉**）

| 参数 | 必填 | 默认 | 说明 |

| ticker | 否 | — | 模式①：聚焦单标的组；都不给则出全榜 |
| trader | 否 | — | 模式②：聚焦单个交易员。**⚠️ 服务端不支持按人查，只能拉全榜后本地过滤**（见下）|

## 两种模式

| 模式 | 触发 | 回答的问题 | 调用 |
|---|---|---|---|
| **① 标的视角**（默认）| 给 ticker，或都不给 | 这只票**谁在做**／现在钱在挤哪些票 | 1 额度 |
| **② 交易员视角** | 给人名 | **这个人**在做什么、值不值得跟 | 1 额度（同一次全榜，本地过滤）|

> ⚠️ **不要说「仓位实时」**——它是**事件驱动**的：有人动了才有新事件。实测 2026-08-01（周六）**全榜最新事件在 6.2 小时前，三次拉取逐字节相同**。
> ⇒ 卡头一律写「**最后事件：<最新 event_time>**」，让用户自己判断新旧，别替他下「实时」这个结论。

> ### ⛔ 模式② 的硬约束，必须写进产出
>
> **服务端按人名查询不生效**（N-59e）：实测 `query="T1 交易员仓位 trader position"` 返回的是**完整热门榜**，与空关键词一致，**零过滤**。人名不是可路由维度。
>
> ⇒ 只能**拉全榜再本地过滤**，因此：
> - ✅ **在榜的人**：可做完整尽调（跨标的敞口 / 对冲 / 战绩 / 三分类）
> - ❌ **不在榜的人**：拿不到任何数据。措辞只能是「**当前榜上没有他**」，**绝不能说「他没有仓位」**——两者不是一回事。
> - ⚠️ 榜本身很小（实测 13 人），且**日内会变**（N-59d）。"这次没查到"不代表"下次也没有"。

**模式② 相对模式① 多给四样东西**（都是单标的视角结构性看不到的）：

| | 为什么标的视角看不到 | 实测 |
|---|---|---|
| **跨标的总敞口** | 每个组只显示他在这一只上的仓 | T1 $380万 分散在 BTC + ETH + SNDK **三个组** |
| **是否对冲** | 组内只表现为"多空各一条"，看不出是同一个人 | T1 ETH 多 $155万 + 空 $95.7万 |
| **显示名归一** | 组与组之间名字可能不同（闸②）| T3 = T3′，真实敞口 $251万 |
| **能力圈三分类** | **上游无此字段**（N-59o）| 见闸④ 第 6 项 |

## 为什么需要这些闸

`profile` 把战绩算好了直接给——这正是危险所在。**用户看到的和数据真正说的，在下面每一行都不一样**：

| 用户看到 | 数据真正说的 | 闸 |
|---|---|---|
| `is_active: true` + $451万 的最大敞口 | **人早就清仓了**——平仓事件不回流，旧仓位永远挂着（T5实测，上游 bot 交叉验证）| **闸①** |
| 两个不同的交易员名字 | **同一个人**——profile 逐字段相同，连刷新时间戳都是同一秒（T3 / T3′实测）| **闸②** |
| `net_direction: "short"` | **7 人做多、1 人做空**——只是那 1 个人的仓位约等于 7 人之和（BTC 实测）| 闸③ |
| `agreement.ratio: 0` | 不是"没有共识"，是**有人同时持多空两腿，字段算不动了**（ETH 实测）| 闸③ |
| `胜率 98% · 盈亏比 5510` | 55 笔里只输过极小的一笔——**盈亏比越离谱，说明亏损样本越少，不是实力越强**（T1实测）| 闸④ |
| `胜率 100% · 净赚 846 万` | **2 笔**。系统自己标的是 `unrated`（T6实测）| 闸④ |
| 战绩数字 | 是**日快照**，而仓位是实时的（N-59i）；且 **`as_of` 不是刷新时间——各人 `summary_refreshed_at` 实测差 2 天**（N-59p）| 闸⑤ |

## 闸① · 陈旧：先过滤幽灵仓，再读任何数字

🔴 **这是唯一一道必须在读数之前跑的闸**——它决定后面所有闸作用在哪些行上。

**问题**：`close` 事件不回流,交易员清仓后 **MCP 仍返回其旧仓位且 `is_active` 恒 `true`**（N-59m）。

> **实测反例（2026-08-01）**：上游实盘监控 bot 显示「T5 当前无持仓」，而 MCP 同日仍返回其 SNDK **$254万** + SKHY **$197万** 两仓，`is_active:true`、`action:"add"`、无任何平仓痕迹。
> **这两仓合计 $451万，是当次全榜的名义第一大敞口（占 38%）**——不过滤就会把幽灵仓写成"最大的钱"。

### 判据（两条并联，命中任一即标「待核」）

| # | 判据 | 实测 |
|---|---|---|
| ① 绝对陈旧 | `now − event_time ≥ 3 天` | T5 SNDK 3.7 天 / SKHY 3.6 天 ✅（08-01）|
| ② 组内落后 | 该仓 `event_time` 比所在组 `symbol_rollup.latest_event_time` 落后 **≥2 天** | 落后 3.7 / 2.9 天 ✅（08-01）|
| **③ 组整体陈旧**（2026-08-03 新增）| **该组自己的 `symbol_rollup.latest_event_time` 距今 ≥3 天** → **整组标待核** | CXMT 组 3.15 天 · XYZ100 组 3.26 天 ✅（08-03）|

### 🔴 为什么必须有第三条：判据 ② 存在结构性失明

**「组内落后」是相对组内最新算的，所以整组一起冷掉时它恒等于抓不到。**

2026-08-03（周一）实测：

| 组 | 组龄 | 组内 4/3 仓的绝对陈旧命中 | 组内落后命中 |
|---|---|---|---|
| CXMT | **3.15 天** | 4/4 全中 | **仅 1 条** |
| XYZ100 | **3.26 天** | 3/3 全中 | **0 条** |

⇒ 若照 v1.3 写的「跨周末则以组内落后为主」执行，**XYZ100 整组会被判为"新鲜"，而它整组 3.26 天没动过**。判据 ③ 正是补这个洞。

> ⚠️ **3 天 / 2 天都是拍的，仅有本批断层支撑，未回测**。
> 🔴 **周末/假期会整体推高「距今」，阈值须按交易日理解**：2026-08-01（周六）复测，正常在场的 T1 已达 **42 小时**未动、T3′ 达 **24.9 小时**——**周一再跑会有一批正常仓位挤进 2–3 天区间**。
> ✅ **2026-08-03（周一）实测坐实了这个预言，而且比预期更狠**：绝对陈旧命中率 **33% → 65%**（13/20 仓）。**该闸在周一基本没有区分力。**
> ⇒ 命中绝对陈旧时，**先看是不是跨了周末**；跨周末则**以判据 ③「组整体陈旧」为主**（不是 ②，理由见下），并在产出里注明当日是周几与命中率。
> 📌 但本批断层很干净：**陈旧簇 3.0–4.8 天、活跃簇 ≤1.8 天，中间无任何仓位**——切点是数据自己给的。
> ✅ **方向是确定的**：`close` 不回流 + `is_active` 恒 true ⇒ **不设闸就必然把幽灵仓当真实敞口**。本批 21 仓中 **7 仓（33%）命中，涉及名义 $486万（40%）**。

### 处置

- 命中的仓位**标「待核」并排除出敞口排名**，但**不删除**——单独一行列出。
- ⛔ **措辞两头都不能说死**：只能写「**≥N 天未观测到变动，可能已平仓**」；不能说"他持有 X"（可能已平），也不能说"他已平仓"（MCP 侧无证据）。

## 闸② · 姓名归一：不要用 `trader` 字符串当主键

实测「**T3**」（BTC 组）与「**T3′**」（SKHY 组）**profile 逐字段完全相同**——149 笔 / 净利 3,095,063 / PF 2.56 / 焦点与弱项数组逐项一致，**连 `summary_refreshed_at` 都是同一秒**（N-59n）。

**不归一的后果**：该员真实敞口 **$251万** 会被拆成 $206万 + $45万 两个人，**"谁的钱最大"排名直接失真**。

→ **按 profile 指纹归一**：`overall.n_trades` + `overall.net_pnl_usd` + `summary_refreshed_at` 三元组相同即判同一人。归一后在产出里注明"已合并显示名 A/B"。

### 🔴 但必须**双向**执行——同名也可能是两个人（N-59s，2026-08-04 新）

实测同一份返回里**两种病同时存在**：

```
BTC 组「T3」出现两次，profile 完全不同：
  #1  tier "A"  · overall 151 笔 · 净利 3,296,931 · refreshed 08-03T02:35:30Z
  #2  tier "—"  · overall   0 笔 · 净利 0         · refreshed 08-04T02:35:13Z
同时 CL 组的「T3′」与 #1 profile 逐字段相同 ← N-59n 同人两名
```

⇒ **两条规则并行**：
- 指纹**相同** → 合并（哪怕名字不同）
- 指纹**不同** → **强制拆开（哪怕名字一样）**，并在产出标注「**同名两个账户**」——否则读者会以为是渲染重复

✅ 服务端是对的：`active_trader_count:8` 把这两条算作 2 人（按 profile 计数）。**错的是显示名，不是计数**。

## 闸③ · 方向：只信人数，不信名义

**过滤之后，这是最重要的一道闸**，因为它拦的是**唯一一个会给出反向结论的字段**。

### ⛔ 三种失效形态（前两种是 2026-08-01 新发现）

**形态 1 · 巨鲸压秤——null 率为 0 也会翻车（N-59j，新）**

实测 BTC 组（8 仓全部有 notional，**null 率 0**）：

```
long:  {count: 7, notional_value_usd: 2,061,400}
short: {count: 1, notional_value_usd: 2,064,433}   ← T3 一人
long_notional_ratio: 0.4996 / short_notional_ratio: 0.5004
net_direction: "short"                             ← 名义口径
agreement: {dominant_direction: "long", dominant_trader_count: 7, ratio: 0.875}  ← 人数口径
```

**7:1 的人数分歧，被一个人的仓位抹成 50:50 并翻成 short。**
⚠️ **这推翻了 N-59a 原来的 workaround**——它说"null 率为 0 时 notional 派生字段才可引用"，**实测 null 率 0 照样反向**。正确纪律是:**notional 方向任何时候都不单独用**。

**形态 2 · 双向持仓打崩 agreement（N-59k，新）**

实测 ETH 组：`active_trader_count: 3` 但 `positions_returned: 4`——**T1同时持有 ETH 多头 155 万与空头 95.7 万**（对冲腿）。结果：

```
long: {count: 2}, short: {count: 2}     ← 4 条腿
agreement: {dominant_direction: "unknown", dominant_trader_count: 0, ratio: 0}
```

**`agreement` 整个退化成 unknown/0/0。** 而 N-59a 恰恰推荐用 `agreement.ratio` 判一致性——**这条路在有双向持仓时是断的**。

> ### 🔴 但「有人双向」只是 unknown 的成因之一（N-59r，2026-08-03 反推）
>
> 实测 **CL 组** `agreement:{unknown, 0, 0, total:2}`，而 `positions_returned(2) == active_trader_count(2)`——**没有任何人双向持仓**。v1.3 的判据在这里完全落空。
>
> **逐组反推出的真实计票规则（5 组 5/5 全中）**：
> `agreement` **按「交易员」计票，不是按「腿」**；每人取其唯一方向；**双向的人不计入分子**（但仍算进 `total_trader_count`）；`ratio = dominant_trader_count ÷ total_trader_count`；**可计票的人里没有严格多数（平局）就整体吐 `unknown/0/0`**。
>
> | 组 | 构成 | agreement | 验算 |
> |---|---|---|---|
> | BTC | 6 长 1 空，无双向 | `long/6/0.857` | 6÷7 ✅ |
> | CXMT | 2 人单向多 + 1 人双向 | `long/2/0.667` | 2÷3 ✅ |
> | XYZ100 | 1 人单向多 + 1 人双向 | `long/1/0.5` | 1÷2 ✅ |
> | **ETH** | 1 长 1 空 + 1 人双向 | **`unknown`** | 双向吃掉一票 → 剩余平局 |
> | **CL** | 1 长 1 空，**无双向** | **`unknown`** | **单向交易员本身就平局** |
>
> ⇒ **`unknown` 一律读作「该组没有多数方向」**，再看 `long.count`:`short.count` 自己判是平局还是被双向吃票。
> ✅ 这条规则反过来是**正面可用的**：`ratio` 的分母是**人数**不是腿数，`dominant_trader_count ÷ ratio` 能反推 `total_trader_count`，可交叉校验 `active_trader_count`。

**形态 3 · null 行被静默排除（N-59a，原有）**
`gross/net_notional`、`long/short_notional_ratio`、`net_direction` **只统计有名义的行**，null 行不参与（不是记 0）。

**形态 4 · 全员 null → 「没数据」被渲染成「多空平衡」（N-59q，2026-08-03 新）**

实测 XYZ100 组：

```
positions_returned: 3 / positions_without_notional: 3    ← 100% 无名义
gross_notional_value_usd: 0 / net_notional_value_usd: 0
long_notional_ratio: 0 / short_notional_ratio: 0
net_direction: "balanced"                                 ← 不是均衡，是没数据
long: {count: 2} / short: {count: 1}                      ← 三条腿全是 20x
```

**`balanced` 与"真的多空对等"在返回值上完全无法区分**；更阴的是 `gross=0` 会让这组在"谁的敞口最大"排序里**沉到最底或被过滤掉**，而它实际有 3 条 20x 的腿。
✅ 对照：同批 ETH 组 `positions_without_notional: 1`（4 中 1），gross 照常给 260 万——**字段是"有多少算多少"，只有全 null 才退化**。

### ✅ 正确读法（四步，不可省）

0. **先做机械判定**：`positions_without_notional == positions_returned` → **命中则 `gross`/`net`/两个 ratio/`net_direction` 五个字段整体作废**，本组只报人数与杠杆，直接跳到步骤 1 并按闸⑥ 措辞输出。
   💡 `positions_without_notional` 是 dev 新加的字段，形态 3/4 现在都可机械判定，**不必再逐仓手算核对**。
1. **先报人数**：`long.count` : `short.count`。
   - `positions_returned > active_trader_count` → **有人双向持仓，必须点名**。
   - ⛔ **但反过来不成立**：相等**不能**推出"没问题"。`agreement` 为 `unknown` 时**另有平局这个成因**（N-59r），此时只能说「该组没有多数方向」，**不要去找那个不存在的双向交易员**。
2. **再看集中度**：算 `最大单仓 notional ÷ gross_notional`。**>40% 即标「单人主导」**（阈值是拍的，未回测；BTC 实测T3 占 50.0%）。
   ⚠️ **2026-08-03 实测：该阈值在当前榜规模下几乎恒真**——5 组里 4 组命中（47.9% / 59.4% / 76.8% / 62.5%），第 5 组因全 null 算不了。
   ⇒ **「命中 40%」本身不构成发现**，别当红旗报。真正值得写的是**具体占比 + 那个人是谁 + 他有没有别的红旗**（如 CXMT 组占 76.8% 的那位 tier D 且正做自己弱项）。
3. **净方向永远带口径**：写「**按人数 7:1 偏多；按名义 50:50，因某单一仓位占 50%**」，**绝不写单一结论**。

## 闸⑤ · 新鲜度：一份返回里两半时间不同

- **仓位/事件侧**：实时（`event_time` 到秒）
- **`profile` 侧**：**日快照**（`as_of` = 日期，`summary_refreshed_at` 约 02:3xZ）

### 🔴 时间锚用 `summary_refreshed_at`，不用 `as_of`（N-59p，2026-08-03 新）

**`as_of` 对同一次返回里的所有人统一等于拉取日，掩盖了各人刷新时间的不同步。**

实测 2026-08-03 一次拉取（**13 个显示名**）：**T1 `as_of` 写 `2026-08-03`，而 `summary_refreshed_at` 停在 `2026-08-01T02:35:53Z`——落后 2 天**；同批其余 12 人全部是 `2026-08-03T02:3x`。且 T1 的数字在两次拉取间逐字未变（55 笔 / PF 5510.64 / 98%）。

⚠️ **危害精确落在最扎眼的那个数上**：闸④ 第 5 项要拆的正是 T1 的「98% 胜率 + PF 5510」，而这组数比同表其他人旧 2 天。按 `as_of` 写「截至 08-03」= **把 08-01 的快照标成 08-03**。

→ **纪律**：战绩一律写「截至 `<该员 summary_refreshed_at>`」，**不写「截至 as_of」也不写「当前」**。同表多人时取各人 `summary_refreshed_at` 的**最小值**做整表口径，**跨度 ≥1 天必须点名最旧的那个人**。

⚠️ `last_30d.n_trades` 是**滚动窗口**，日增量 ≠ 当期平仓数；要算当期成交只能用 `overall.n_trades` 增量，且只在**该员 `summary_refreshed_at` 推进时**才算（N-59i/N-59p）。
⚠️ **全榜是实时快照，日内会变**（N-59d：实测 18 分钟内某组交易员数 4→5）。**"榜上没有它"≠"已平仓"。**

## 闸⑥ · 不可计价标的

部分永续标的没有价格源（非上市/合成）。**取价是可选的第二次调用（`metrics` 侧，另计 1 额度，见「额度哨兵」）**；实测 **CXMT**（长鑫存储，未上市）、**XYZ100**（合成指数）取价返回 `results:{}` + `status:"ok"`，且 keyword 被**静默丢弃**（N-59c/N-59g）。

→ 这类仓位**跟方向、不编价格**，单独标 `unpriced` 并报条数。本 Skill 本来就不算收益，此闸只用于"别对用户承诺能看到这仓赚没赚"。

⚠️ **不可计价有两个来源，别混为一谈**：

| 来源 | 判据 | 措辞 |
|---|---|---|
| **标的无价格源**（N-59c/g）| 取价返回 `results:{}` + `status:"ok"`（**仅在启用取价的第二次 `metrics` 调用时可判**）| 「该标的无公开价格源，无法计价」|
| **平台没给名义**（N-59q）| `positions_without_notional == positions_returned` | 「**平台未提供金额，敞口无法计价**」——⛔ **不能写「多空平衡」，也不能写「无敞口」** |

实测 XYZ100 **两条同时命中**（既是合成指数、又全组无名义）；CXMT 只命中第一条（4 仓里 3 仓有名义）。

> ### ✍️ 【一句话】写法铁律
>
> **先原样引用用户最可能被吸引的那个数字，再当场拆掉它。** 不要从系统措辞、评级理由或元数据切入——用户的眼睛本来就落在那几个大数上，从别处起手是绕远路。
>
> | ❌ 从元数据切入 | ✅ 从他看到的数字切入 |
> |---|---|
> | "系统给他 tier A，理由写着「近 30 天仍在盈利」——那是 2 笔交易…" | "**他的「98% 胜率、盈亏比 5510」几乎全来自 30 天以前**——近 30 天只有 2 笔、1 胜 1 负、净赚 6,296 美元。而眼下他压着 380 万以上敞口，四仓全 ≥10x。" |
>
> **三条细则**：
> ① **≤2 行**。超了就是在铺垫，不是在下判断。
> ② **不用形容词**（"辉煌""惊人""恐怖"）——数字自己会说话，加形容词反而稀释。
> ③ **用「而」把过去与现在对撞**：前半句是他的历史战绩，后半句是他此刻的敞口。这个转折本身就是判断。

> ⛔ **模式② 最容易犯的错**：把「陌生区」写成「他不擅长」。上游只给了两个名单，**第三种状态是无信息，不是负面信息**。

> ✂️ **三段可省**（视数据而定，不硬凑）：`已合并显示名`（无别名时省）· `双向对冲`（无对冲时省）· `盲区`（`caution_symbols` 非空时省）。**但【口径】里的三闸结果一行不能省**——用户得知道你查过。

### ✂️ 去噪三原则

| 原则 | 具体 |
|---|---|
| **红旗 × 仓位 才是重要性** | 有红旗但仓位微小的**不占版面**（实测 T7 $6,255 命中"零亏损不可验证"，但不值得列）|
| **只报会改变判断的** | 无红旗且不主导的仓位 → 合并成一行"无红旗：…"，不展开明细 |
| **同一信息只出现一次** | 取消独立的「红旗汇总」段（与内联重复），红旗收进表格一列 |

> 实测对照：同一批数据按标的组织 ≈ 90 行、逐仓列 21 条；按人聚合 + 三原则去噪后 ≈ 45 行、列 6 条，**且多出"前三人占 90%"与"显示名重复"两个原始数据看不到的发现**。

**⛔ 硬要求**：

1. **六道闸必须落在纸面上，且闸①②必须最先跑。** 用户能从这张卡拿到的唯一独家价值，就是知道那三个数字不能怎么读。**口径声明省一条，这支就退化成一个会误导人的裸榜。**
2. **解读优先于陈列。** 判别：**把数字换成别的数，这句话还成立吗？**

| ❌ 复述 | ✅ 解读 |
|---|---|
| "BTC 组净方向偏空" | "**8 个人里 7 个做多,但净方向报的是空**——因为空的那位一个人的仓位约等于另外七个人加起来。而 BTC 正好在他自己的历史弱项名单里" |
| "T1盈亏比 5510" | "**盈亏比 5510 不是强,是他几乎没输过**——55 笔里那唯一一笔亏损小到让分母接近 0。十天前这个数字还是 ∞、评级还是 provisional" |
| "T6胜率 100%" | "**2 笔交易,系统自己标的是 unrated**——846 万的净利来自两笔,这不构成可跟的记录" |

3. **红旗主动顶出**，不能埋在明细里等人自己找。
3b. **通过的闸也要写进产出**（一行即可）。用户无法从沉默里分辨"查了没问题"与"根本没查"——实测T1卡里"陈旧/归一/计价三闸均通过"就是有效信息，不是废话。
4. **不给买卖建议、不给仓位配比、不承诺收益。** 输出是"这单值不值得进一步研究"。
5. **不做跟单账本**——已于 2026-07-30 论证否决（数据形态不支持回测：无逐笔历史、`entry_price` 覆盖率 6%（N-59b）、日频轮询观察覆盖率仅 9–28%）。详见 CHANGELOG 同日条目。

⚠️ **执行顺序**：闸① 陈旧 → 闸② 姓名归一 → 再跑闸③~⑥。前两道是**过滤**，决定后面作用在哪些行上；顺序反了会把幽灵仓写进结论。

## 额度哨兵

`signal` 单次 = **1 额度**（全榜或单标的均是一次调用，fanout 不额外计费）；**启用闸⑥ 取价时另加 1 次 `metrics`（+1 额度）**。跑完读 `meta.quota`。

## 已知边界

| 边界 | 性质 | 处置 |
|---|---|---|
| 名义方向可与人数方向相反 | 上游（N-59j，null 率 0 也会）| 两个口径都给，附单人占比 |
| `agreement` 退化为 `unknown` | 上游（N-59k/**N-59r**）| 两个成因：有人双向（`positions_returned > active_trader_count`）**或单向交易员平局**。一律读作「无多数方向」，按人数自判 |
| **rollup 把 `entry_price` 当名义加总** | **上游疑似 bug（N-59l）** | **手算 `long.notional` 之和核对 `gross`**；对不上时以逐仓明细为准 |
| 不能按交易员姓名检索 | 上游（N-59e）| 拉全榜本地过滤；措辞用"当前榜上没有" |
| 无 unrealized PnL / 无逐笔历史 | 数据形态（N-59b）| **不算收益**，本 Skill 只做尽调不做账本 |
| 部分标的无价格源 | 上游（N-59c）| 标 `unpriced`，不编价 |
| 全榜日内变动 | 实时快照（N-59d）| "榜上没有"≠"已平仓" |
| tier 会因单笔样本跃迁 | 数据特性（实测T1 P→A）| tier 当**当次读数**，不当稳定标签 |
| **平仓不回流 → 幽灵仓** | 上游（N-59m）| **闸① 必须最先跑**。实测确认案例：T5 $451万（全榜第一大敞口）实为幽灵仓；08-03 复验 5 组 `actions.close` 全为 0 |
| 同一人多个显示名 | 上游（N-59n）| 按 profile 指纹归一，别用 `trader` 字符串当主键 |
| **同一显示名两个人** | 上游（**N-59s**）| 指纹不同则**强制拆开**并标注「同名两个账户」；显示名两个方向都不可当身份键 |
| **「陌生区」上游无字段** | 上游（N-59o）| `current_symbol_caution` 只标弱项；擅长与陌生都返 `false`。**客户端自行三分类**，且陌生区只能表述为"系统无判断"|
| **`as_of` 掩盖各人刷新不同步** | 上游（N-59p）| 时间锚一律用 `summary_refreshed_at`；同表取最小值，跨度 ≥1 天点名最旧者 |
| **全组无名义 → 伪装成「多空平衡」** | 上游（N-59q）| 先判 `positions_without_notional == positions_returned`；命中则金额字段整体作废，只报人数与杠杆，不得按 $0 排序 |
