# Earnings Screener — 财报季超预期扫描

**一句话**：每个财报季，从几百家刚发完财报的美股里，挑出「业绩确实大幅超出华尔街预期」**并且**
「电话会上管理层亲口说了产品不够卖」的那几家，把原话一并给你。

### 它替你干的活

财报季（每年 1、4、7、10 月）每周上百家美股发财报。想从里面找出真正值得研究的，得做两件事：

先从一堆数字里挑出**营收和利润明显比市场预期高**的公司；再去翻这些公司的**财报电话会记录**——
每份四五万字——看管理层有没有说过「订单排到明年」「产能跟不上」「产品价格还能往上走」这类话。

一个人翻，一个季度也翻不了几家。

### 怎么做的

1. 从当天成交最活跃的股票、以及近期财报报道里，捞出刚发过财报的美股
2. 逐个核对营收和每股收益到底超出预期多少，不够格的直接淘汰
3. 对剩下最好的几家，把整份电话会记录从头读一遍，找七类"生意很旺"的表述
4. **只有「业绩」和「说法」两项都达标的，才进最终名单**

### 你拿到什么

一张短名单。每家附上管理层的**原话、是谁说的、是主动讲的还是被分析师追问出来的**——
以及同样重要的：**同一场会上他们说过的坏消息**（比如要大幅加码开支、某块业务在下滑）。

### 为什么两项都要看

只看数字，会挑到财报好看但管理层心里没底的公司；只看管理层怎么说，会挑到话说得漂亮但业绩没兑现的。
**两边对得上，才算信号。**

> ⚠️ **这不是买入清单**，输出的是"值得进一步研究"的线索。关键词是管理层的说法，不是已经兑现的事实。

## 一、从四步法到实现

原方法是 A 股语境的人肉流程，四步：财报季 → 挨个看业绩大增的 → 扫电话会高景气表述 → 2+3 叠加才关注。
映射到实现：

| 原方法 | 实现 | 关键决策 |
|---|---|---|
| **① 财报季** | `days` 窗口 + 财报新鲜度闸 | 光有窗口不够——必须验 `beat_miss.date` 真在窗口内。实测有标的拿两个月前的旧季数据通过了全部数值闸 |
| **② 业绩大增** | 四道硬闸：营收 / 市值 / 得分 / 新鲜度 | **营收是主锚，不是 EPS**。EPS 易被一次性损益和低基数扭曲——实测某航空股 EPS 名义 +400%，只因预期基数是 $0.03 |
| **③ 关键词** | Top N 逐字稿全文扫 7 类正向表述 | 命中**必须附原文摘录 + 发言人 + 语境**。给不出原文的不算命中；区分「管理层主动说」与「被分析师问出来」 |
| **④ 叠加** | 业绩闸 ≥24 **且** 关键词闸 ≥20 | 两道闸独立，缺一不可。只有业绩是「数字好看」，只有关键词是「管理层嘴上说得好听」 |

### 比原方法多的两样

**反向关键词减分。** 原方法只找多头证据，这是典型的确认偏误。实测某标的七类正向词全中，
而同一场电话会里 CFO 上修资本开支、预告下年再加码、承认库存减记——**空头论据全出自管理层自己的嘴**。
只扫正向词会完整错过这一半。

**GAAP 口径错位检测。** 上游同一份返回里可能并存 GAAP 与非 GAAP 的 EPS，**没有任何字段标明口径**。
实测某标的显示超预期 +100%，同一 payload 里 GAAP 净亏 110 亿美元。只读 beat_miss 会把巨亏季读成完美超预期。

## 二、被实测否决的方案

记在这里是为了防止后来人（包括未来的自己）好心把它们加回来。**每条都有实测证据，不是设计偏好。**

### 1. 市场级财报日历作发现腿 —— 最重要的一条

初版设计的发现腿①就是它，实现前的探针直接否决。

服务端等效 `ORDER BY date ASC, symbol ASC LIMIT 50`，且 `limit` 入参不被尊重。截断因此是**按字母序**的——
GOOGL / MSFT / NVDA / TSLA 在任何财报密集日都必然出局。

最尖锐的例证：某个交易日返回的 50 行里**无后缀美股 = 0 只**；Alphabet 倒是出现了，
以法兰克福上市的 `ABEA.F` 身份。同一家公司，`GOOGL` 永远进不来。

**客户端杠杆已穷尽**（2026-07-29 复测仍未修复）：`limit` / `country` / `include_penny_stocks` /
改写 query / 逐日拆分，**五种全部返回逐行一致的结果**。

> 💡 **如果 dev 修好了**，这条腿可以加回来——那时它才是真的"全市场"而不是字母切片。
> caveats 的 N-22 条目记了回滚动作。判断是否已修的自查调用附在 Skill 正文顶部。

### 2. 纯新闻单腿发现

考虑过只用 `news`（0 额度、覆盖历史窗口）。否决理由是覆盖面——冷门中小票没有媒体报道就完全捞不到。
日历腿死掉后改用**异动榜**补位，双腿混合的初衷（覆盖面）因此得以保留。

### 3. 价格闸（`price < $5` 剔仙股）

看起来合理，实测**误杀**：某标的股价 $3.31、市值 $131 亿，业绩闸达标却被价格闸拦下。
市值闸是更准的同类过滤，价格闸只贡献误杀——已删除。

### 4. 用「距财报日天数」预判逐字稿是否滞后

假设是"逐字稿要几天才发布，刚发完财报去拉必然拿到上一季"。**被同日相反结果证伪**：
两只股票同一天发财报，隔天去拉，一只拿到当季、一只拿到上一季。日历不可能是原因。

真正的判据是 `transcript[0].period` 恒等于 `latest_quarter.period`，用两个字段的日期间隔可零成本预判。

### 5. 该判据的 60 天阈值

先取 60 天，**被 42 样本边界探针证伪**。45~70 天区间不是空白，而是**中概 ADR 的系统性栖息带**
（报告节奏比美股本土慢一个月左右），实测其中三只全部返回当季——按 60 天会把它们误判滞后而跳过。

改为 **90 天**，且这个数是从机制推的：间隔的物理含义就是财报公布滞后天数，
数据陈旧时会多出整整一个财季，两种状态只可能差一个季度。

> 🔑 **这条留下的教训写进了 Skill**：**阈值画在空白区之前，先确认那真的是空白。**

## 三、验证时点

**本目录所有结论实测于 2026-07-27 ~ 2026-07-29。** MCP 行为会变，其中多条是上游 bug 的规避——
**上游修好之后，这些规避会朝反方向出错**。

Skill 正文顶部附了 5 条自查调用（日历 / country 过滤 / 数组参数 / ticker 字典 / 逐字稿判据），
隔一段时间再用先跑一遍，几分钟。caveats 登记表里每条都记了「Dev 修复后回滚动作」。
