## 调用约定（2026-10-03 实测）

`metrics` 的入参分工是：**`keywords` 数组放标的 / series_id，`query` 放意图词**。

- **不要把标的塞进 query 串**：实测 `query="GCUSD SIUSD DXUSD USDJPY 行情"` 只解析出 USDJPY，**黄金、白银、美元指数三个 `*USD` 代码被静默丢弃且不报错**。数组写法四个都能取到。
- **每次调用最多 5 个 keywords**。丢项会写进 `meta.warnings`——每次调用后读一遍，并以"请求清单与返回 `symbol` 的差集"为准判断缺口。
- **经济日历只写 `query="economic calendar"`，必须带 `country="US"` 和 `sort_by="hot"`**：不带 `sort_by` 时按时间排，50 行只覆盖一两天，CPI / PCE 会被国债拍卖、EIA 周报挤出去；query 里写指标名会被解析成别的关键词，传 `keywords` 会被静默忽略。
- FRED 指标带 `categories=["macro"]`；行情带 `asset_type="tradfi"`。
- 黄金必须用 `GCUSD`（`GOLD` 会取到 Gold.com 这只美股）。
- 如果客户端不接受数组入参（报 `-32602`），FRED 指标可退回 `query="<series_id>"` 单个直查；`*USD` 商品代码没有可用的 query 串写法，只能标"数据不可用"。
- 黄金看盘常在亚洲时段跑：美股时段的行情返回的是上一个常规收盘。有 `_quote_session` 字段就按它判；没有这个字段时分两类看 `as_of`：`^VIX` 不在美东 9:30–16:00 内标"最近收盘"；外汇、商品（`GCUSD` / `SIUSD` / `DXUSD` / `USDJPY`）近 24 小时交易，不套美股时段，`as_of` 距调用时刻 1 小时内就按实时报价用，超过才标"最近报价"并写出 `as_of`（2026-10-08 实测这四个品种的 `as_of` 比调用时刻晚 5~20 分钟）。周末的外汇报价开高低收相同属于陈旧报价，标"周末报价"。

## 评分框架

每个指标 -2 到 +2。`最终分数 = 50 + Σ(指标得分 × 权重) × 25`

| 区间 | 含义 |
|---|---|
| 80-100 | 强烈利多 |
| 65-79 | 偏多 |
| 50-64 | 中性偏多 |
| 40-49 | 中性偏空 |
| 25-39 | 偏空 |
| 0-24 | 强烈利空 |

> ⚠️ **下面的打分阈值于 2026-10-08 按回测分布校准（v1）**：用 2023-01 起 192 周数据，按各指标的历史分布定档，目的是让各档出现频率合理、同一份数据每次打出同一个分——**不是按预测力调的**。相对 2026-10-01 的 v0 草案，改了 ①④⑤⑥⑧⑨ 六项阈值和 ⑧ / ③ 的权重（见 ⑧ 的说明），②⑦⑩⑪⑫ 维持。改动时直接改表。

> **③ 的说明**：偏鸽变化 = 下次会议降息概率的一周变化 − 加息概率的一周变化（百分点），加息、降息周期都适用。用日历的议息结果判断加 / 降息，不要用 `FEDFUNDS` 月均值推（月中调息会被拆进两个月）。FedWatch 取不到时偏鸽变化按 0 计，并注明。多个来源给出的一周前概率不一致时各算一遍；得分不同取更接近 0 的档，并在明细里写明各来源的数字和日期，优先采信注明"据 CME FedWatch"的主流媒体。35 天日历只覆盖最近一次议息会议；若该次为未调息，用 Web 确认再前一次 FOMC 的结果后再判"近 3 个月"。**当天读数常搜不到**（2026-10-08 实测，最新能找到的是 3~6 天前的报道）：用能找到的最新一次读数，对比**该读数日期往前 7 天**的读数，不要拿它去比"今天往前 7 天"；两个日期都写进明细。一周内概率可能大幅跳动（同一实测里 9-29 加息概率 68.1%、10-01 为 24.4%、10-02 为 18.3%），锚点差两三天就会换档。
> **⑧ 的保鲜期**：WGC 季报发布超过 60 天，得分乘以 0.5（季报一季才出一次，过期数据不应满权重托底）。
> **⑧ 的权重**（2026-10-08 用户拍板）：由 12% 降到 6%，降下来的 6% 加给 ③（10% → 16%），第一层合计 41%、第三层 19%。理由：WGC 首次公布值常被大幅修订（2026Q1 从 244 吨改成 57 吨），而且回测里这一项常年偏多，平均把总分抬高 3.2 分。
> **⑨ 的取数**：首选 SPDR 官方逐日持仓存档 `https://api.spdrgoldshares.com/api/v1/historical-archive?product=gld&exchange=NYSE`（xlsx，2004 年至今；2026-10-08 回测实测可用），取最新一行和 30 天前最近一行的持仓吨数。存档取不到再用中文快讯：用快讯时，取最新一条和约 30 天前的一条，两条日期相距 28~35 天即可，明细里写明起止日期和各自来源。
> **⑩ 的说明**：结果离档位边界 ±3 美元以内时注明"临界"。**⑩ 的保鲜期**（2026-10-08 用户拍板）：数据日期距今超过 5 天，得分乘以 0.5。thevaultreport 页面上的数据日期要读出来写进明细——2026-10-08 实测该页数据日期是 09-29，比调用日早 9 天；春节、国庆长假 SGE 休市，溢价会停在节前。metalcharts.org 的上海金页面实测只渲染占位符，取不到数。
> ⑫ 的逻辑：金银比下行说明白银跟涨甚至领涨，贵金属行情在扩散；上行说明只有黄金独撑。美东盘中跑时，日线最新一行是当日盘中价（`close` 随现价变动），明细里注明"当日未收盘"。
> **⑪ 的取数**：只认日历里两行——`Core Inflation Rate MoM`（这就是核心 CPI 环比，名字里没有 "CPI"）和 `Core PCE Price Index MoM`。不要用 `CPI (…)`、`CPI s.a`、`Inflation Rate (…)`，它们是总体 CPI 的指数点位，拿来对比会把方向判反。"符合"指实际与预期在公布精度上相等。
> **⑪ 的保鲜期**：按两项中**较早**的那次发布算，超过 3 周得分乘以 0.5。
> **"4 周变化"的基准**（①②⑦⑫）：取 `observation_date` ≤ 最新日期 − 28 天的最近一行。档位区间一律左闭右开（例如 VIX 正好 17 落在 17 ~ 23）。

## 层得分、方向与矛盾度

```
层得分 = Σ(该层指标得分 × 权重) ÷ 该层权重合计        （范围 −2 ~ +2，保留一位小数）
层方向 = 层得分 > +0.5 为 ↑；< −0.5 为 ↓；其余为 →          （按未取整的层得分判断，显示时再保留一位）
最终分数四舍五入取整后再对照区间（例如 39.25 → 39 → 偏空；区间表只有整数，不取整会落进 39 与 40 之间的空档）
```

用脚本算时，权重按整数百分点代入（例如第二层 (−12 − 8 + 5) ÷ 30），或先把层得分保留 4 位小数再判方向：2026-10-08 实测第二层正好是 −0.5，浮点直算得 −0.5000000000000001，会被误判成 ↓。得分是整数、权重是整数百分点，层得分正好落在 ±0.5 并不罕见。

矛盾度只看前三层：

| 矛盾度 | 条件 | 含义 |
|---|---|---|
| 低 | 三层里没有同时出现 ↑ 和 ↓ | 信号可靠 |
| 高 | 实际利率层与另外两层的方向都相反（两层都是反方向，不含 →）| 基准层被两层同时否定，观望 |
| 中 | 其余所有情况 | 信号需观察 |

**层内分歧**（不改分，只在卡片上标注）：同一层里同时有 +2 和 −2 的指标，就在矛盾度后面加一句"层内分歧：[指标 A] vs [指标 B]"。

## 分析流程

### 第一步：取数（三批，每批 ≤4 路并行）

**Batch 1**
```
metrics(keywords=["DFII10","T10YIE","BAMLH0A0HYM2"], categories=["macro"], limit=22)   # ①②⑦（日频，22 条≈4 周）
metrics(keywords=["GCUSD","SIUSD","DXUSD","USDJPY","^VIX"], query="行情", asset_type="tradfi")   # ④⑤⑥ 现价
metrics(keywords=["DXUSD","USDJPY"], query="均线 指标", period=50, limit=1, asset_type="tradfi")  # ④⑤ 的 EMA50
```

**Batch 2**
```
metrics(keywords=["GCUSD","SIUSD"], query="历史走势", time_range="1m", limit=25, asset_type="tradfi")   # ⑫
metrics(query="economic calendar", country="US", time_range="35d", sort_by="hot", limit=50)   # ③ 议息结果、⑪ 核心 CPI / PCE 的 actual / estimate
metrics(query="economic calendar", country="US", date_from="<今天>", date_to="<今天+14天>", sort_by="hot", limit=30)   # 下次关键事件
```
35 天窗口带 `sort_by="hot"` 能一次拿到最近一期的核心 CPI、核心 PCE、非农和议息结果（2026-10-03 实测）。但 50 行不一定铺满 35 天：2026-10-08 实测只回溯到 09-10（窗口起点 09-03），核心 CPI（09-11 发布）排在第 44 行，再早几天发布就会掉出首页——所以要按事件名逐行核对，不能默认"35 天都在"。
**日历返回 `status:"partial"` 加"候选上限已满"的降级警告是常态**，不要因此补调：目标事件行都拿到就继续；缺哪行，用 `meta.pagination.next_cursor` 以相同参数翻一页；仍缺再 Web。

**下次关键事件**：前瞻窗口里第一条本 Skill 用到的事件（核心 CPI / 核心 PCE / 非农 / `Fed Interest Rate Decision`）；窗口里没有就取第一条 `impact=="High"` 的事件。`date_from=<今天>` 会把今天已公布的行排在最前（2026-10-08 实测前三行是当天已出 `actual` 的初请数据），`actual` 非空或时间已过的行跳过。下次 FOMC 议息日若在窗口外，用 Web 确认后另列。
向后的窗口不要超过 14 天：服务端候选上限只覆盖约两周，窗口再长也排不到更远的事件；下次 FOMC 议息日在 14 天外时，另用 Web 确认日期。

**Batch 3（Web）**
```
CME FedWatch 下次会议降息 / 加息概率（含一周前的值）   # ③
World Gold Council 央行购金（最新季度）      # ⑧
SPDR 官方持仓存档 GLD 近 30 日变化        # ⑨
SGE 上海金收盘价对 LBMA 的溢价               # ⑩
```

每次 `metrics` 调用后核对 `meta.warnings` 是否有丢项、`results` 里是否每个请求的标的都有数据。

### 第二步至第五步

逐指标对照阈值表打分（记录原始数值、数据日期、落在哪一档）→ 套公式算综合分（缺失指标按 0 分计、权重不转移）→ 算层方向和矛盾度 → 一段话综合判读。卡片上的"主要支撑 / 拖累"按加权贡献（保鲜期折算后的得分 × 权重）排序，不按原始得分——原始得分 −1 的指标常有四五个并列。

## 意图判断

- **默认**："黄金宏观" → 概览卡片 + 完整明细
- **快速**："黄金现在几分" → 只出概览卡片
- **深度**：追问某一层 → 展开该层每个指标的数据和打分依据
- **对比**："和上周比" → 只有会话里有上一次评分时才做；没有就说明没有历史记录

## 数据缺失处理

| 场景 | 处理 |
|------|------|
| 某指标取不到数（`results` 为空、差集有缺口、Web 检索失败）| 该指标标"数据不可用"，**按 0 分计、权重不转移**（相当于向中性收缩），并在卡片上标注缺失项。不要把它的权重分给同层其余指标——实测黄金看盘 GLD 缺失后，权重转给一份两个月前的央行购金数据，把总分抬高了 3 分 |
| Followin MCP 整体不可用 | 说明连不上数据源，不输出评分 |
| 缺失指标 ≥ 3 个 | 评分照出，但在卡片和明细里都标"数据覆盖不足，可靠性降低"。第三层三个指标全靠 Web 检索，最容易缺 |

---

## 输出约束

- 每个得分都要带原始数值、数据日期和来源；没数据就标缺，不估
- 不给操作建议，不做价格预测（不回答"金价能到 XX 吗"）
- 分数描述当前宏观环境，不代表未来涨跌概率（2026-10-08 回测：综合分对金价未来 4 / 12 周收益无预测力）
- 矛盾度照实写
- 脉冲层标明是否已过保鲜期
- 语言跟随用户
