# Live Positions — 实盘尽调台

**一句话**：有人正在用真钱做这只票——**他值不值得跟？**

两种问法都行：**「谁在做 SNDK」**（标的视角）或 **「T1在做什么」**（交易员视角）。

## 它解决什么问题

`trader_position` 把交易员的战绩**算好了直接给你**：胜率、盈亏比、评级、擅长什么、避开什么。这看起来省事，实际上是最危险的地方——**几个最扎眼的数字，恰好最会骗人**，而散户的眼睛正好只落在那几个数上。

下面每一条都是 2026-08-01 一次实跑里真实出现的：

- 表上写着 **净方向：空**。实际是 **7 个人做多、1 个人做空**——只不过那 1 个人的仓位约等于另外 7 人加起来。
- 表上写着 **共识度 0**。这不是"大家没共识"，是**有人同时开了多空两条腿，这个字段算不动了**。
- 表上写着 **胜率 98%、盈亏比 5510**。盈亏比 5510 不是强得离谱，是**他几乎没输过**——55 笔里那唯一一笔亏损小到让分母接近 0。十天前这个数字还是"∞"、评级还是"存疑"。
- 表上写着 **胜率 100%、净赚 846 万美元**。**2 笔交易**。系统自己给的评级是"样本不足，不予评级"。
- 那个把整组方向翻过来的巨仓，**它的标的正好在这位交易员自己的历史弱项名单里**。
- 表上写着某人持有 **451 万美元**、`is_active: true`——**上游监控 bot 显示他当前无持仓**。平仓事件不回流，旧仓位就一直挂着，而这是全榜最大的一笔钱。
- 表上是**两个不同的交易员名字**——实际是**同一个人**，profile 逐字段相同，连刷新时间戳都是同一秒。

**这支的产品不是那张表，是拦住这七种读法的六道闸。**

---

## 六道闸各拦什么

> **前两道是过滤，必须最先跑**——它们决定后面四道作用在哪些行上。

### 闸① · 陈旧：先剔幽灵仓

交易员清仓后，MCP 仍返回旧仓位且 `is_active` 恒为 `true`。判据**三条并联**：距今 ≥3 天未动 · 比同组最新事件落后 ≥2 天 · **整个标的组已经 ≥3 天没动静**。

第三条是 08-03 实跑补上的，因为第二条有个盲点：**它是跟同组最新的比，所以整组一起冷掉时它什么都抓不到**。实测有一组整整 3.26 天没动过，第二条判据命中 **0 条**。

⚠️ 还有一件事得知道：**周一跑这支，第一条判据会失灵**——周末两天把所有仓位的"距今"整体推高，命中率从周六的 33% 跳到周一的 **65%**，等于没筛。这时以第三条为主，并且卡上会写明当天是周几。

命中的**不删除、只标「待核」并排除出敞口排名**；措辞两头都不说死——只能写「N 天未观测到变动，可能已平仓」。

### 闸② · 姓名归一

同一个人可能有多个显示名。按 `overall.n_trades` + `net_pnl_usd` + `summary_refreshed_at` 三元组指纹归一，**不要用名字当主键**——否则一个人被算成两个、敞口被拆开，「谁的钱最大」直接排错。

### 闸③ · 方向：只信人数，不信名义

**唯一一个会给出反向结论的字段。** 净方向是按"钱"算的，不是按"人"算的——一个巨鲸就能把 7:1 的人数分歧抹平并翻向。

所以它**永远给两个口径**：「按人数 7:1 偏多；按名义 50:50，因为某一仓占了 50%」——**绝不写单一结论**。

另外它会主动查一件事：**有没有人同时持多空两腿**（用返回里的仓位条数与交易员人数对比）。有的话点名，因为那会让"共识度"字段直接失效。

⚠️ **但"共识度 0"还有第二种成因，08-03 实跑才搞清楚**：如果做多和做空的人数正好一样多（比如 1 比 1），字段同样会显示 0——**这时候根本没有人持双向**。

我们把这个字段的算法整个反推出来了，五个标的组验算全中：**它是按「人」算的，不是按「腿」算的**；一个人同时持多空就不计票；**剩下的人如果打平，就直接显示 0**。所以"共识度 0"只该读成「**这组没有多数方向**」，不该去找一个并不存在的双向交易员。

### 闸④ · 战绩：六项 sanity check

零亏损 ≠ 神（分母为 0，盈亏比**不可验证**）· 小样本高比值 · **正在做自己的弱项** · 高杠杆 · **盈亏比极大值同样不可读作实力** · **能力圈三分类**（见下）。

命中任何一条，红旗直接顶到最前面,不埋在明细里。

并且**系统自己写的评级理由原文照登**——"small sample (5 closed trades); positive signal not confirmed"、"downgraded because last 30d net PnL turned negative"，比我们自己撰的措辞权威得多。

### 闸⑤ · 新鲜度：一份返回里两半时间不同

**战绩是日快照，仓位是事件驱动**（有人动了才有新事件，不是持续刷新）。战绩说「截至某日」，仓位说「最后事件在 X」——**都不说「当前」**。

实测 2026-08-01（周六）：全榜最新事件在 **6.2 小时前**，间隔数小时的三次拉取**逐字节相同**。周末尤其安静。

🔴 **而"截至某日"这个日期，不能信表面那个字段。** 数据里有个日期字段对所有人写的都是"今天"，但每个人的战绩**实际刷新时间是分开的**——实测同一次拉取里，有一个人的战绩停在**两天前**，其余十二人都是当天。

麻烦的是这个人恰好是全榜钱最多的那位，而他那组"胜率 98%、盈亏比 5510"正是最扎眼的数字。所以卡上一律取**全表最旧的那个刷新时间**当口径，谁最旧就点谁的名。

而且全榜是实时快照、日内会变——**"榜上没有它"≠"已经平仓了"**。

### 🆕 能力圈三分类（sanity check 第 6 项）

上游给了两个名单：他擅长什么（`focus_symbols`）、他在什么上吃过亏（`caution_symbols`）。**但落在两个名单之外的标的，没有任何字段标记**——而实测这类占了 **21%**，且其中 **3/4 的杠杆 ≥10x**。

典型：一个 focus 全是加密的交易员，在股票永续上开了 **20x**——那是他全部仓位里最高的杠杆。

⚠️ 措辞要准：陌生区只能说「**系统对他在这个标的上没有判断**」，**不能说「他不擅长」**。真正值得提示的是**组合**：无信息 + 高杠杆。

### 闸⑥ · 不可计价标的

"不可计价"有两种，得分开说：

**① 标的本身没有价格源**——未上市的长鑫存储、合成指数这类，取价会返回空但**不报错**。

**② 平台压根没给金额**——08-03 新发现的一种。某一组三条腿的金额**一条都没给**，于是汇总栏显示"总额 $0、方向：多空平衡"。**那不是平衡，那是没有数据**；而三条腿全都是 20 倍杠杆。

第二种更阴，因为"$0"会让这组在"谁的钱最大"里**沉到最底**。同样的事在按人汇总时会再发生一次：实测有两个人聚合出来是 **$0**，实际一个持 25 倍、一个持 20 倍——**全榜杠杆最高的一档，差点被静默排到榜尾**。所以卡上遇到这种一律标「**下界**」，并且不按这个 $0 排序。

这两类仓位都只跟方向、不编价格。

## 它不做什么

**① 不算收益、不做跟单账本。** 这不是偷懒——2026-07-30 专门验证过一轮并**论证否决**：数据形态不支持（没有逐笔历史、开仓价覆盖率只有约 10%、日频观察最多只能看到 9–28% 的真实成交）。详见 [`CHANGELOG`](../CHANGELOG.md) 同日条目。

**② 不能按交易员姓名检索。** 人名不是可查询的维度——只能拉全榜再本地过滤。所以话必须说准：**「当前榜上没有他」，而不是「他没有仓位」**。

**③ 不给买卖建议、不给仓位配比。** 输出是"这单值不值得进一步研究"。

## 怎么用

**安装**（MCP 已接通的前提下）：

```bash
cp "Live Positions"/*.md ~/.claude/commands/
```

**触发**——说人话就行：

| 你说 | 得到 |
|---|---|
| `谁在做 SNDK` · `SNDK 实盘持仓` | 该标的所有在场交易员 + 逐个红旗 |
| `钱在挤哪些票` · `真金白银在买什么` | 全榜：当前有货的所有标的组 |
| `T1在做什么` · `这个交易员能跟吗` | **交易员卡**：跨标的总敞口 / 是否对冲 / 战绩 / 能力圈三分类 |
| | ⚠️ 服务端不支持按人查——拉全榜本地过滤；找不到只能说「当前榜上没有他」，**不是「他没有仓位」** |

**一次调用 = 1 额度**（全榜与单标的都一样）。
