# /live-position-diligence $ARGUMENTS

**这张表最扎眼的三个数字——净方向、胜率、盈亏比——恰好是最会骗人的三个。散户的眼睛正好落在那儿。本 Skill 不复述它们，只把它们钉住。**

> **版本**：v1.2 ｜ **实测验证于 2026-08-01**（全榜实跑两次 `66880966` / `2ab45ef2`；5 组 / 21 仓 / 13 名交易员）
> **v1.2 变更**：新增**模式②交易员视角**（跨标的敞口/对冲/显示名归一/能力圈三分类）+ sanity check 第 6 项「陌生区」（N-59o）
> **v1.1 变更**：新增**闸① 陈旧（幽灵仓）**与**闸② 姓名归一**（N-59m/n）——两者是**过滤**，必须在其余四闸之前跑；输出模板改为**按人聚合**并加去噪三原则
>
> ⚠️ 本文所有 ⚠️ 与阈值都是实测结果或明确标注的拍脑袋值，不是推断。MCP 行为会变。
> 通用红线与 `trader_position` 全部已知坑见 [`references/followin-mcp-caveats.md`](../references/followin-mcp-caveats.md) 的 **N-59a~i** 与本轮新增的 **N-59j~o**，本文内联的是镜像，冲突以该文件为准。
>
> **隔一段时间再用，先花两分钟自查这 4 条**：
> ① 找一组 `long.count` 与 `short.count` 悬殊的，看 `net_direction` 是否与人数方向一致 → 不一致 = N-59j 仍在
> ② 找一组 `positions_returned > active_trader_count` 的（有人双向持仓），看 `agreement.dominant_direction` → 为 `"unknown"` = N-59k 仍在
> ③ 手算某组 `long.notional` 之和 vs `gross_notional_value_usd` → 对不上且差额等于某行 `entry_price` = N-59l 仍在
> ④ 全榜找 `event_time` 最旧的一仓，看 `action` 有无 `close`、`is_active` 是否仍为 `true` → 仍 true 且无 close = **N-59m 幽灵仓风险仍在**（本批 33% 的仓位 ≥3 天未动）

## 参数

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| ticker | 否 | — | 模式①：聚焦单标的组；都不给则出全榜 |
| trader | 否 | — | 模式②：聚焦单个交易员。**⚠️ 服务端不支持按人查，只能拉全榜后本地过滤**（见下）|

## 两种模式

| 模式 | 触发 | 回答的问题 | 调用 |
|---|---|---|---|
| **① 标的视角**（默认）| 给 ticker，或都不给 | 这只票**谁在做**／现在钱在挤哪些票 | 1 额度 |
| **② 交易员视角** | 给人名 | **这个人**在做什么、值不值得跟 | 1 额度（同一次全榜，本地过滤）|

> ### ⛔ 模式② 的硬约束，必须写进产出
>
> **服务端按人名查询不生效**（N-59e）：实测 `query="T1 交易员仓位 trader position"` 返回的是**完整热门榜**，与空关键词一致，**零过滤**。人名不是可路由维度。
>
> ⇒ 只能**拉全榜再本地过滤**，因此：
> - ✅ **在榜的人**：可做完整尽调（跨标的敞口 / 对冲 / 战绩 / 三分类）
> - ❌ **不在榜的人**：拿不到任何数据。措辞只能是「**当前榜上没有他**」，**绝不能说「他没有仓位」**——两者不是一回事。
> - ⚠️ 榜本身很小（实测 13 人），且**日内会变**（N-59d）。"这次没查到"不代表"下次也没有"。

**模式② 相对模式① 多给四样东西**（都是单标的视角结构性看不到的）：

| | 为什么标的视角看不到 | 实测 |
|---|---|---|
| **跨标的总敞口** | 每个组只显示他在这一只上的仓 | T1 $380万 分散在 BTC + ETH + SNDK **三个组** |
| **是否对冲** | 组内只表现为"多空各一条"，看不出是同一个人 | T1 ETH 多 $155万 + 空 $95.7万 |
| **显示名归一** | 组与组之间名字可能不同（闸②）| T3 = T3′，真实敞口 $251万 |
| **能力圈三分类** | **上游无此字段**（N-59o）| 见闸④ 第 6 项 |

## 为什么需要这些闸

`profile` 把战绩算好了直接给——这正是危险所在。**用户看到的和数据真正说的，在下面每一行都不一样**：

| 用户看到 | 数据真正说的 | 闸 |
|---|---|---|
| `is_active: true` + $451万 的最大敞口 | **人早就清仓了**——平仓事件不回流，旧仓位永远挂着（T5实测，上游 bot 交叉验证）| **闸①** |
| 两个不同的交易员名字 | **同一个人**——profile 逐字段相同，连刷新时间戳都是同一秒（T3 / T3′实测）| **闸②** |
| `net_direction: "short"` | **7 人做多、1 人做空**——只是那 1 个人的仓位约等于 7 人之和（BTC 实测）| 闸③ |
| `agreement.ratio: 0` | 不是"没有共识"，是**有人同时持多空两腿，字段算不动了**（ETH 实测）| 闸③ |
| `胜率 98% · 盈亏比 5510` | 55 笔里只输过极小的一笔——**盈亏比越离谱，说明亏损样本越少，不是实力越强**（T1实测）| 闸④ |
| `胜率 100% · 净赚 846 万` | **2 笔**。系统自己标的是 `unrated`（T6实测）| 闸④ |
| 战绩数字 | 是**日快照**（`as_of`），而仓位是实时的——两半新鲜度不同（N-59i）| 闸⑤ |

## 闸① · 陈旧：先过滤幽灵仓，再读任何数字

🔴 **这是唯一一道必须在读数之前跑的闸**——它决定后面所有闸作用在哪些行上。

**问题**：`close` 事件不回流,交易员清仓后 **MCP 仍返回其旧仓位且 `is_active` 恒 `true`**（N-59m）。

> **实测反例（2026-08-01）**：上游实盘监控 bot 显示「T5 当前无持仓」，而 MCP 同日仍返回其 SNDK **$254万** + SKHY **$197万** 两仓，`is_active:true`、`action:"add"`、无任何平仓痕迹。
> **这两仓合计 $451万，是当次全榜的名义第一大敞口（占 38%）**——不过滤就会把幽灵仓写成"最大的钱"。

### 判据（两条并联，命中任一即标「待核」）

| # | 判据 | 实测（T5）|
|---|---|---|
| ① 绝对陈旧 | `now − event_time ≥ 3 天` | SNDK 3.7 天 / SKHY 3.6 天 ✅ 命中 |
| ② 组内落后 | 该仓 `event_time` 比所在组 `symbol_rollup.latest_event_time` 落后 **≥2 天** | 落后 3.7 / 2.9 天 ✅ 命中 |

> ⚠️ **3 天 / 2 天都是拍的，仅有本批断层支撑，未回测**。
> 📌 但本批断层很干净：**陈旧簇 3.0–4.8 天、活跃簇 ≤1.8 天，中间无任何仓位**——切点是数据自己给的。
> ✅ **方向是确定的**：`close` 不回流 + `is_active` 恒 true ⇒ **不设闸就必然把幽灵仓当真实敞口**。本批 21 仓中 **7 仓（33%）命中，涉及名义 $486万（40%）**。

### 处置

- 命中的仓位**标「待核」并排除出敞口排名**，但**不删除**——单独一行列出。
- ⛔ **措辞两头都不能说死**：只能写「**≥N 天未观测到变动，可能已平仓**」；不能说"他持有 X"（可能已平），也不能说"他已平仓"（MCP 侧无证据）。

## 闸② · 姓名归一：不要用 `trader` 字符串当主键

实测「**T3**」（BTC 组）与「**T3′**」（SKHY 组）**profile 逐字段完全相同**——149 笔 / 净利 3,095,063 / PF 2.56 / 焦点与弱项数组逐项一致，**连 `summary_refreshed_at` 都是同一秒**（N-59n）。

**不归一的后果**：该员真实敞口 **$251万** 会被拆成 $206万 + $45万 两个人，**"谁的钱最大"排名直接失真**。

→ **按 profile 指纹归一**：`overall.n_trades` + `overall.net_pnl_usd` + `summary_refreshed_at` 三元组相同即判同一人。归一后在产出里注明"已合并显示名 A/B"。

## 闸③ · 方向：只信人数，不信名义

**过滤之后，这是最重要的一道闸**，因为它拦的是**唯一一个会给出反向结论的字段**。

### ⛔ 三种失效形态（前两种是 2026-08-01 新发现）

**形态 1 · 巨鲸压秤——null 率为 0 也会翻车（N-59j，新）**

实测 BTC 组（8 仓全部有 notional，**null 率 0**）：

```
long:  {count: 7, notional_value_usd: 2,061,400}
short: {count: 1, notional_value_usd: 2,064,433}   ← T3 一人
long_notional_ratio: 0.4996 / short_notional_ratio: 0.5004
net_direction: "short"                             ← 名义口径
agreement: {dominant_direction: "long", dominant_trader_count: 7, ratio: 0.875}  ← 人数口径
```

**7:1 的人数分歧，被一个人的仓位抹成 50:50 并翻成 short。**
⚠️ **这推翻了 N-59a 原来的 workaround**——它说"null 率为 0 时 notional 派生字段才可引用"，**实测 null 率 0 照样反向**。正确纪律是:**notional 方向任何时候都不单独用**。

**形态 2 · 双向持仓打崩 agreement（N-59k，新）**

实测 ETH 组：`active_trader_count: 3` 但 `positions_returned: 4`——**T1同时持有 ETH 多头 155 万与空头 95.7 万**（对冲腿）。结果：

```
long: {count: 2}, short: {count: 2}     ← 4 条腿
agreement: {dominant_direction: "unknown", dominant_trader_count: 0, ratio: 0}
```

**`agreement` 整个退化成 unknown/0/0。** 而 N-59a 恰恰推荐用 `agreement.ratio` 判一致性——**这条路在有双向持仓时是断的**。
✅ 对照：CXMT 组也有人双向（T2），但因为还有 2 名单向交易员，`agreement` 给出 `long / 2 / 0.667`——**能算就算，算不动就吐 unknown**。

**形态 3 · null 行被静默排除（N-59a，原有）**
`gross/net_notional`、`long/short_notional_ratio`、`net_direction` **只统计有名义的行**，null 行不参与（不是记 0）。`net_direction="balanced"` 同时覆盖"真均衡"与"全员 null"两种情况。

### ✅ 正确读法（三步，不可省）

1. **先报人数**：`long.count` : `short.count`，并**用 `positions_returned` 与 `active_trader_count` 对比**——不等就说明有人双向持仓，必须点名。
2. **再看集中度**：算 `最大单仓 notional ÷ gross_notional`。**>40% 即标「单人主导」**（阈值是拍的，未回测；BTC 实测T3 占 50.0%）。
3. **净方向永远带口径**：写「**按人数 7:1 偏多；按名义 50:50，因某单一仓位占 50%**」，**绝不写单一结论**。

## 闸④ · 战绩：六项 sanity check

展示任何交易员战绩前逐条过。前四条来自 N-59 正面产出，第 5–6 条是 2026-08-01 新增。

| # | 红旗 | 判据 | 实测样例（2026-08-01）|
|---|---|---|---|
| 1 | **零亏损 ≠ 神** | `pnl_ratio_infinite: true` → 分母为 0，盈亏比**不可验证** | T7 7 笔全胜、`pnl_ratio: null` → tier **P**，`rating_reason` 自陈 *"not verifiable; provisional"* |
| 2 | **小样本高比值** | `n_trades` 小而 `pnl_ratio` 高 | T6 **2 笔净赚 846 万、胜率 100%** → 系统标 `unrated`。⚠️ **`n < 10` 一律不给百分比**（1 笔 100% 是伪精确）|
| 3 | **正在做自己的弱项** | `current_symbol_caution: true` | T3 **10x 空 BTC $206 万**，而 BTC 就在他自己 `caution_symbols` 里。⚠️ **且这正是翻转全组方向的那一仓**（见闸③）|
| 4 | **高杠杆** | `leverage ≥ 10` 单独提示 | 21 仓里 8 仓 ≥10x，**T8 BTC 50x**。杠杆不进 tier 评级，但决定这仓能不能活到方向被验证 |
| 5 | **⚠️ 盈亏比极大值同样不可读作实力**（新）| `pnl_ratio > 100` | T1 `pnl_ratio: 5510.64` / 胜率 98% / 55 笔。**比值越离谱说明亏损样本越少或越小，不是越强**。<br>⚠️ 该员 07-20 时还是 `pnl_ratio_infinite: true` / 100% / tier **P**——**多出的那一笔亏损让 tier 从 P 跳到 A**。tier 会因单笔样本跃迁，别当稳定标签 |

| 6 | **⚠️ 能力圈三分类：「陌生区」上游无字段**（新，N-59o）| `标的 ∈ caution` → 弱项｜`∈ focus` → 擅长｜**两者皆非 → 陌生** | `current_symbol_caution` **只标弱项**；擅长与陌生返回值都是 `false`，消费端无法区分。<br>实测 19 仓：**擅长 12（63%）· 弱项 3（16%）· 陌生 4（21%）**。<br>⚠️ **陌生区 4 仓中 3 仓 ≥10x**：JS 做 ETH **25x**（其 focus 全是股票永续）· T1 做 SNDK **20x**（focus 全是加密，且这是他最高杠杆）· T4 做 BTC 11x（tier D）。**4 仓中 3 仓跨资产类别。** |

> ### ⚠️ 第 6 项的表述必须校准
>
> `focus_symbols` 的**导出口径未文档化**——可能按成交频次，也可能按表现（从 `caution_symbols` 的语义反推像是后者）。
> ⇒ 陌生区只能写「**系统对他在这个标的上没有判断**」，**不能写「他不擅长」**（无证据）。
> ✅ 真正值得单独顶出的是**组合**：`陌生区 × leverage ≥10x` —— **无信息 + 高杠杆**。

> ✅ **`rating_reason` 必须跟着数字一起展示**——它是系统自己写的白话解释（*"small sample (5 closed trades); positive signal not confirmed"*、*"downgraded because last 30d net PnL turned negative"*），比任何我们自撰的措辞都权威。
> ⛔ **数字一律取结构化字段**（`overall` / `last_30d`），**`summary` 散文里的数字比结构化字段旧**（N-59h：实测差 25 笔），只当定性描述读。

### tier 速查

| tier | 含义 | 处置 |
|---|---|---|
| A / B | 有足够样本且净盈利 | 可展示，仍须过六项 check |
| C | 接近盈亏平衡 | 展示但标注"接近打平" |
| **D** | **系统性亏损**（实测T4 PF 0.67 / 486 笔 / 净亏 343 万；T2 PF 0.42）| **🔴 避雷位，主动顶出** |
| **P** | provisional——样本不足或盈亏比不可验证 | **🔴 不可当"好交易员"展示** |
| **—** | unrated（样本 <3 笔）| 只报仓位，**不报战绩** |

## 闸⑤ · 新鲜度：一份返回里两半时间不同

- **仓位/事件侧**：实时（`event_time` 到秒）
- **`profile` 侧**：**日快照**（`as_of` = 日期，`summary_refreshed_at` 约 02:3xZ）

⚠️ 战绩一律说「**截至 `as_of`**」，**不要说"当前"**（N-59i）。
⚠️ `last_30d.n_trades` 是**滚动窗口**，日增量 ≠ 当期平仓数；要算当期成交只能用 `overall.n_trades` 增量，且只在 `as_of` 变化时才算。
⚠️ **全榜是实时快照，日内会变**（N-59d：实测 18 分钟内某组交易员数 4→5）。**"榜上没有它"≠"已平仓"。**

## 闸⑥ · 不可计价标的

部分永续标的没有价格源（非上市/合成），实测 **CXMT**（长鑫存储，未上市）、**XYZ100**（合成指数）取价返回 `results:{}` + `status:"ok"`，且 keyword 被**静默丢弃**（N-59c/N-59g）。

→ 这类仓位**跟方向、不编价格**，单独标 `unpriced` 并报条数。本 Skill 本来就不算收益，此闸只用于"别对用户承诺能看到这仓赚没赚"。

```
【一句话】
<1–2 句。过滤之后真正的格局是什么。必须是判断，不是统计。>
```

### 模式② · 交易员卡（同一次调用，本地过滤）

```
👤 <交易员> 尽调卡 · <日期>
战绩截至 as_of=<date>（日快照）｜仓位实时
<若归一过>已合并显示名：A = B（profile 指纹一致）

【一句话】
<1–2 句：他现在在做什么、最该注意哪一点。必须是判断。>

【战绩】（截至 as_of）
tier <X>｜<n> 笔｜胜率 <y>%（n<10 不给百分比）｜盈亏比 <z>｜净 <±$>

系统评级理由："<rating_reason 原文>"
<命中的 sanity check 逐条，含第 6 项>

【当前持仓】总敞口 $X，分布 N 个标的

【能力圈对照】

· 战绩为日快照；仓位实时但平仓事件不回流
```

> ⛔ **模式② 最容易犯的错**：把「陌生区」写成「他不擅长」。上游只给了两个名单，**第三种状态是无信息，不是负面信息**。

### ✂️ 去噪三原则

| 原则 | 具体 |
|---|---|
| **红旗 × 仓位 才是重要性** | 有红旗但仓位微小的**不占版面**（实测 T7 $6,255 命中"零亏损不可验证"，但不值得列）|
| **只报会改变判断的** | 无红旗且不主导的仓位 → 合并成一行"无红旗：…"，不展开明细 |
| **同一信息只出现一次** | 取消独立的「红旗汇总」段（与内联重复），红旗收进表格一列 |

> 实测对照：同一批数据按标的组织 ≈ 90 行、逐仓列 21 条；按人聚合 + 三原则去噪后 ≈ 45 行、列 6 条，**且多出"前三人占 90%"与"显示名重复"两个原始数据看不到的发现**。

**⛔ 硬要求**：

1. **六道闸必须落在纸面上，且闸①②必须最先跑。** 用户能从这张卡拿到的唯一独家价值，就是知道那三个数字不能怎么读。**口径声明省一条，这支就退化成一个会误导人的裸榜。**
2. **解读优先于陈列。** 判别：**把数字换成别的数，这句话还成立吗？**

| ❌ 复述 | ✅ 解读 |
|---|---|
| "BTC 组净方向偏空" | "**8 个人里 7 个做多,但净方向报的是空**——因为空的那位一个人的仓位约等于另外七个人加起来。而 BTC 正好在他自己的历史弱项名单里" |
| "T1盈亏比 5510" | "**盈亏比 5510 不是强,是他几乎没输过**——55 笔里那唯一一笔亏损小到让分母接近 0。十天前这个数字还是 ∞、评级还是 provisional" |
| "T6胜率 100%" | "**2 笔交易,系统自己标的是 unrated**——846 万的净利来自两笔,这不构成可跟的记录" |

3. **红旗主动顶出**，不能埋在明细里等人自己找。
4. **不给买卖建议、不给仓位配比、不承诺收益。** 输出是"这单值不值得进一步研究"。
5. **不做跟单账本**——已于 2026-07-30 论证否决（数据形态不支持回测：无逐笔历史、`entry_price` 覆盖率约 10%、日频轮询观察覆盖率仅 9–28%）。详见 CHANGELOG 同日条目。

⚠️ **执行顺序**：闸① 陈旧 → 闸② 姓名归一 → 再跑闸③~⑥。前两道是**过滤**，决定后面作用在哪些行上；顺序反了会把幽灵仓写进结论。

## 额度哨兵

单次 = **1 额度**（全榜或单标的均是一次调用，fanout 不额外计费）。跑完读 `meta.quota`。

## 已知边界

| 边界 | 性质 | 处置 |
|---|---|---|
| 名义方向可与人数方向相反 | 上游（N-59j，null 率 0 也会）| 两个口径都给，附单人占比 |
| 双向持仓打崩 `agreement` | 上游（N-59k）| 用 `positions_returned` vs `active_trader_count` 差值兜底识别 |
| **rollup 把 `entry_price` 当名义加总** | **上游疑似 bug（N-59l）** | **手算 `long.notional` 之和核对 `gross`**；对不上时以逐仓明细为准 |
| 不能按交易员姓名检索 | 上游（N-59e）| 拉全榜本地过滤；措辞用"当前榜上没有" |
| 无 unrealized PnL / 无逐笔历史 | 数据形态（N-59b）| **不算收益**，本 Skill 只做尽调不做账本 |
| 部分标的无价格源 | 上游（N-59c）| 标 `unpriced`，不编价 |
| 全榜日内变动 | 实时快照（N-59d）| "榜上没有"≠"已平仓" |
| tier 会因单笔样本跃迁 | 数据特性（实测T1 P→A）| tier 当**当次读数**，不当稳定标签 |
| **平仓不回流 → 幽灵仓** | 上游（N-59m）| **闸⑤ 必须最先跑**。实测确认案例：T5 $451万（全榜第一大敞口）实为幽灵仓 |
| 同一人多个显示名 | 上游（N-59n）| 按 profile 指纹归一，别用 `trader` 字符串当主键 |
| **「陌生区」上游无字段** | 上游（N-59o）| `current_symbol_caution` 只标弱项；擅长与陌生都返 `false`。**客户端自行三分类**，且陌生区只能表述为"系统无判断"|
| **不能按交易员名字查** | 上游（N-59e）| 模式② 由全榜本地过滤实现；"榜上没有"≠"没有仓位" |
