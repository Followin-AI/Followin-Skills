# Failure Modes — 实跑踩过的坑（泛化版）

> 本框架的多数"⚠️ 强制"规则都是事故换来的。这里按失效模式归档：**症状 → 根因 → 修法（对应哪条规则）**。
> 所有案例已泛化（标的/金额/账号匿名），失效模式本身是通用的。

## 输入端

### F1 — 只拉了部分名单就写日报（输入端漏比落盘漏更隐蔽）
**症状**：日报看起来"完整"，实际只拉了 3/12 个账号——漏的恰好包括两个最高质量账号和唯一的反方。
**根因**：落盘门禁只保证"拉到的都写了"，保证不了"该拉的都拉了"。
**修法**：全量拉取 + 覆盖表每账号显式 ✅/⚪/❌ + 高优账号漏拉零容忍（Step 2 门禁）。

### F2 — 用 search 代替逐账号拉取
**症状**：search 报"无新东西"，正经逐账号拉满后发现大量内容。
**根因**：`$cashtag` 检索对**不带 $ 标签的账号**（多数中文 KOL）系统性失效。
**修法**：search 只作补充验证，绝不作"无新信号"的唯一依据。

### F3 — 闭市/瘦窗口就不拉
**根因**：先入为主"没东西"是经验主义陷阱——非交易时段 KOL 仍在发推（且常是深度长文时段）。
**修法**：预期产出少 ≠ 不拉；瘦窗口照拉，落盘走 lite 协议省的是写不是读。

### F4 — 重大事件后拿初期快照下结论
**症状**：财报后第一拉读到"+9%"，实际是盘后初期，收盘完全不同。
**修法**：财报/政策/黑天鹅后 1h 内再拉完整区间（day high/low/close），双源交叉。

## 提炼端

### F5 — 把"新信号"和"当前状态"混着追加
**症状**：一天 3 次拉取层层 append，叠成 6 层补丁——同一文件里现金占比出现两个互相矛盾的值，最后全文返工。
**修法**：日报分区（状态区 OVERWRITE / 事件流 APPEND），矛盾时状态区直接改+事件块记一行修正（Step 9.6）。

### F6 — 同一事实落 N 处镜像 → 漂移
**症状**：持仓表在 dashboard 里停在两天前的价格，日报里却是最新的——读者不知道信哪个。写盘量的 60-70% 是在维护镜像。
**修法**：Daily 写分析、Daily-Index 写 TLDR、其他文件写指针；banner 只留最新 1 条（Step 9.6 多批次小贴士）。

### F7 — 板块文件没真更新，只改了索引日期
**症状**：日报板块汇总标了新信号，板块累积文件本体 22h 没动。
**修法**：`sector-sync` 声明 + hook 逐个验声明文件 mtime + critic 交叉校验三层兜底（Step 10.9/10.95）。

### F8 — "该建没建"与"久未提没归档"（覆盖核对 vs 声明核对）
**症状**：某标的高频出现 3 个批次才被"注意到"建档——门禁查不到"该建没建"。
**修法**：门禁的「Sectors 全板块扫描」逐行三态判定 + critic 特查非持仓标的；文件多了以后可加机械覆盖审计（→ advanced-extensions.md §6）。

## 数字端

### F9 — 编数字（最危险的失效）
**症状**：策略输出里出现"回调到 $X 建仓 / 减 N 股 / +3% trigger"——全是拍的。
**修法**：每个数字带 `[数据]` 或 `[原则]` 来源标签；没依据 = 只给定性方向或直说不知道。

### F10 — 分母没核实就报占比红线
**症状**：只记了交易账户余额、漏了账户外现金+货基 → 误报"现金占比破红线"，方向完全反了。
**修法**：现金口径必含近现金；分母存疑时禁报具体 %，只给定性 + 标"待确认"。

### F11 — 实盘快照"价值"列当成仓位变化
**症状**：价格跌 → 快照"价值"跌 → 误读为"减仓"。
**根因**：价值 = shares × 当前市价，不是成本/数量。
**修法**：加减仓只看**变动事件流**；辅证 = 加权开仓价变向（低位加仓→成本降，按比例减→成本不变）。

### F12 — 同名 crypto 劫持 ticker 查询
**症状**：查某光通信公司的 fundamentals 返回 `asset_kind: crypto`。
**修法**：`categories=["market","fundamentals"]` + query 带公司全名；仍失败 → 标"暂无 PT 数据"，不编。

## 信号判读端

### F13 — 同源信号重复计数
**症状**：同一人的推特账号 + 实盘群账号被当成两个独立背书。
**修法**：跨渠道身份核实，同人计 1 个信号源。

### F14 — 高频 whip-saw 实盘被逐次跟随
**症状**：某实盘 4 天内同一标的进出 4 次——每次动作都被解读出"含义"。
**修法**：单次动作无跟随价值，只看净敞口与板块轮向；"首次动锚仓"才是事件。

### F15 — 投行评级的承销商水分
**症状**：某 IPO 新股连跌后突然 9 家投行集中 Buy + 高目标价。
**根因**：承销商有 IPO 后静默期，期满集中发自家承销股的研报——"独立性"打折。
**修法**：评级潮先查发布方是否承销商 + 时点是否静默期刚过。

### F16 — 把"分析机构报告"当一手信源
**症状**：某机构报告称关键技术路线大幅延期 → 板块单日 -8~-17%；隔天产业方高管公开否认延期。
**修法**：机构报告 vs 产业一手（管理层/官方表态）分层记录；报告引发的大跌先查"动机+track record"再定性"逻辑杀 or 情绪杀"。

## 第三方数据源端（接研报 / 外部信号后新增，全部实测）

### F17 — 把「提到 X 的研报」说成「X 的研报」
**症状**："MU 本周有 10 篇研报覆盖"——实际 `subject_report_returned_count: 0`，10 篇全是 KIOXIA/SK海力士/UMC 等别家研报里**捎带提到** MU。
**根因**：接口把 `subject_reports` 和 `mention_reports` 分开返回，只看总数会合并成一个错误结论。
**修法**：引用必须写明"出自 <subject> 的研报，X 为 mention"；两个计数分开报。

### F18 — 研报接口默认没有时间窗口
**症状**：日报里"今日新增研报"混进一周前的旧报告。
**根因**：不传 `date_from/date_to` 时返回 `time_scope: "all_available_reports"`。
**修法**：任何进日报/周报的研报查询必须传窗口（传后变 `report_date_window`）；研报本身低频，日频拉常返 0 篇属正常。

### F19 — 用了一个没被填充的字段
**症状**：某个"变动 %"列整页每一行都是 0.00%，据此写出"没有变化"的结论。
**根因**：上游未填充该字段，而同一行里的绝对值字段（如股数、金额）是真的。
**修法**：**任何字段在整页每一行都是同一个值（尤其是 0）时，先怀疑它没被填充，别当数据用**——改用同行的绝对值字段自己算。这条对任何第三方数据源都成立。

### 其他速记
- 集中输出（同作者一天 5+ 条同标的）= 叙事完整但无独立验证，标注待验证。
- KOL 改口（几小时内翻向）单独标注，比观点本身更有信息量。
- 多账号引用同一份机构数据 = 同源不是共识，看首发时间。
- 52w 高位的 KOL 共识 = 常已 priced-in。
- IPO 新股无技术分析（"52w 低"就是上市以来低点）。
- 个股单独跌+板块没跟 = momentum 破位；板块同步跌 = 系统性事件——两者决策含义相反。
