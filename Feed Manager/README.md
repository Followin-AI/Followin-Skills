# Feed Manager — 美股信息流管理

**你关注了十几个讲股票的人。这支每天替你读一遍，并且记住他们说了什么。**

**拆解**：剥掉段子和广告，按标的 / 板块 / 反方拆成结构化条目。
**归档**：逐日累积成可查的档案——三周前谁在 $85 说的多，五秒能翻到。

---

## 这是什么

不是"再给你推一批热点"。这支 Skill 只处理**你自己那份名单**：把他们近 N 小时的推文拉全，剥掉段子和广告，按标的和板块整理成日报，**并且逐日累积成可查的档案**。

跑一周之后，你会拥有三样原本不会有的东西：

- **一个可查的历史** —— "三周前谁在 $85 说的多"，五秒能查到
- **一份决策日志** —— 每笔交易记着当时为什么买，到期提醒你回看对错，教训自动写进下次的买卖前检查表
- **一个反方存档** —— 反方观点单独累积、永不删除，专治"只记得支持自己的信息"

## 为什么不直接让 AI 帮你读推特

因为**不加约束地读，会产生四类看不见的错**。下面每一条都是这套框架实跑撞出来、然后用机制堵住的：

- **漏账号不会有告警**。拉了 3/12 个账号也能写出一份看起来很完整的日报——漏掉的恰好是唯一的反方。→ 每次强制列覆盖表，每个账号显式标"已拉 / 已拉但没内容 / 拉取失败"。
- **漏推文更隐蔽**。一次调用只返一页（实测 20 条），高产账号或断档补拉时盖不住窗口，**剩下的静默消失**。→ 脚本机械检测"本页最早一条是否仍晚于起点"并告警。
- **引用推被当成本人观点**。实测某宏观账号 **19/20 条是引用推**——被引原文是数字的出处，自引则是他在回看自己早先的判断。字段名对不上时，这层信息整个消失。→ 标记逐条打在 digest 上，自引单独标。
- **AI 张口就编价位**。"回调到 $X 建仓"——那个 X 是拍的。→ 全程硬约束：每个数字必须能追溯到数据源或明确原则，**没依据就只给定性方向**。

## 它给你什么

| 你说 | 它做 |
|---|---|
| 「跑一下 KOL」 | 拉全名单 → 日报 → 更新每个标的和板块的累积笔记 → 汇报最该看的 3 点 |
| 「补一下昨晚的」 | 从上次断点增量拉，**合并进当天同一份日报**（不会变成两份打架的文件） |
| 「我买了 XXXX 100 股 @ $85」 | 更新持仓 + 标的 + 板块笔记，并**建一条决策记录**（含 1周/1月/3月回顾提醒） |
| 「XXXX 现在能买吗」 | 跑 5 项买卖前检查，列完状态**让你自己决定** |
| 「给我个止损策略」 | 给 4-5 个**带依据**的触发条件候选，**不会拍一个百分比给你** |
| 周末「跑周报」 | 5 节复盘：持仓/板块演变、KOL 行为、账号质量 review、**你自己的决策对错复盘**、下周日历 |

### 三道门禁（不用操作，每次自动跑）

| # | 门禁 | 拦住什么 |
|---|---|---|
| 1 | 拉取覆盖 | **账号级**——该拉的都拉了吗（覆盖表逐个显式标态） |
| 2 | 翻页回溯 | **推文级**——每个账号的窗口拉全了吗（脚本告警） |
| 3 | 收尾落盘 | **文件级**——拉到的都写了吗（Stop hook 机械校验 mtime + 板块同步声明） |

外加一个条件触发的完整性审查子代理：反扫原始推文，找"在 dump 里但没进任何文件"的信号，特查**反方信号**和**非持仓板块**（两者最容易被乐观叙事盖掉）。

## 它不做什么

- **不喊单、不预测价格、不替你决定买卖。** KOL 喊了就引用并标注是谁说的，自己不背书。
- **不编数字。** 没有数据或原则支撑的价位/百分比它不给——这是特性不是 bug。
- **不接券商。** 持仓和成交要你口头告诉它；忘了报，浮盈和仓位占比会一路错下去且**没有告警**。
- **不是热点发现器。** 它只看你指定的名单。想看全网 KOL 在喊什么 → [`Community Skill/c4_social-pulse`](../Community%20Skill/c4_social-pulse.md)；想看真金白银的仓位 → [`Trader Diligence`](../Trader%20Diligence/README.md)。

## 怎么用

**前提**：[Followin MCP](https://followin.io/en/mcp) 已接入 Claude Code。用到 `twitter`（拉推文）+ `metrics`（报价）+ `signal`（外部共识对照）。

**安装**（在 Followin-Skills 仓库根目录下）：

```bash
# 先看会不会撞名
ls ~/.claude/skills/ 2>/dev/null | grep stock-kol-watch

# 没有输出 → 安全，直接拷
cp -rn "Feed Manager/skills/"* ~/.claude/skills/
```

**两种用法，先低后高**：

| | 🅱️ 快速简报 | 🅰️ 长期累积 |
|---|---|---|
| 产出 | 只在对话里出简报，**不写任何文件** | 日报 + 每标的/每板块累积笔记 + 决策日志 + 周报 |
| 配置 | 无 | 一个文件夹路径（`KOL_VAULT`） |
| 什么时候用 | 试用 / 偶尔扫一眼 | 想建自己的投研档案 |

**先花 5 分钟试一次**（零配置）——装完直接说：

> 「用这 5 个账号跑个快速简报：@jukan05 @aleabitoreddit @nft_hu @xiaomustock @qinbafrank」

（这 5 个是内置的公开参考账号，⚠️ 举例用，**非推荐、非投资建议**。正式用前务必换成你自己的 8-15 个，**并补 1-2 个稳定唱空的**——名单变成全员看多是最危险的盲区。）

**升级到 🅰️**：`export KOL_VAULT="/你的笔记库/Stock-Watch"`，然后说「初始化 vault 并跑一下 KOL」。

**花费**：一次日报 ≈ **名单账号数 + 翻页数** 个 `twitter` 额度 + 每个标的 1 个 `metrics` 额度。⚠️ `twitter` 有月度配额（返回里 `meta.quota` 可查），名单越大烧得越快。

**输出长这样**（真实产出片段，账号已匿名）：

> ⭐ **今日最重要**
> 1. 三星代工目标年内 100% 稼动（现 70-80%），驱动是 HBM4 用 4nm 做 base die ——
>    但真正门槛是 **2nm 良率从 60% 区间进 70% 区间**，不是稼动率本身
>    〔@账号A 08-03 07:28Z · 原推链接〕
>
> 🔴 **反方：本批 0 条** —— 这是**你名单的结构性缺口**，不是市场没有反方。
